# Bitpunk UX 언어 — "Bitpunk Phosphor" (v0.1, M9 진행 중)

이 문서는 **규범**이다. M9에서 확정되며, 이후 모든 마일스톤(M10 보안 저장의 PIN·잠금 화면, M11 백업 도구, M12 업데이트 화면, M13 기능, M14 가이드)이 따른다.
새 부품이나 규칙이 필요하면 먼저 이 문서의 변경을 제안하고 승인받은 뒤 쓴다. (로드맵 원칙 7)
근거: [M9_PLAN.md](milestones/M9_PLAN.md), 목업 캔버스 "Bitpunk Phosphor UI".

장마다 확정된 단위를 적는다. 아직 "예정"인 장은 해당 단위에서 채운다.

## 0. 원칙 (확정, M9 계획)

1. **기능 보존이 최우선.** 모양·위치·조작만 바뀌고 계산·검증·출력은 바이트 단위로 같다. ([기능 대장](FEATURE_INVENTORY.md))
2. **밝기가 곧 중요도.** 녹색 하나의 밝기로 위계를 만든다. 호박색은 주의, 적색은 위험에만.
3. **보이지 않던 검사를 보여 준다.** 기기가 확인한 것을 로그 줄(`[ OK ]` …)로.
4. **정보가 있는 곳에는 비를 내리지 않는다.** 비는 부팅·화면 보호·긴 계산 중에만.
5. **QR은 효과 밖.** 밝은 판 위 검은 모듈, 조용한 여백 4모듈.
6. **색만으로 구분하지 않는다.** 모든 상태에 기호가 함께 있다.
7. **움직임은 최소.** 깜빡임은 커서 1 Hz뿐.
8. **한 키, 같은 자리.** 같은 키는 어디서나 같은 뜻, 키 막대는 늘 맨 아래.
9. **주소는 4자씩 같은 밝기로.** 앞뒤만 강조하지 않는다(주소 중독 공격).

## 2. 격자 (확정, M9-1) — `bp_ui::grid`

- 800×480 = **64열 × 20행**, 칸 12×24 px, 좌우 여백 16 px. ASCII 1칸, 한글 2칸.
- 행 0 상태줄 · 행 1 구분선 · 행 2–17 내용(16줄) · 행 18 구분선 · 행 19 키 막대.
- 위치는 `grid::x(col)`, `grid::y(row)`, 글자는 `grid::text_y(font, row, rows)`로 칸 안에 놓는다. 구분선 `grid::rule(row)`, 상자 `grid::frame(..., double)`(위험 상자는 이중선).
- (M9-3부터 공통 부품이 이 격자 위에 그려지며, 화면 순회가 칸 맞춤을 검사한다.)

## 4. 공통 부품 (확정, M9-3) — `bp_ui::widgets`

| 부품 | 규칙 |
|---|---|
| 상태줄 (`status_bar`, 행 0–1) | 왼쪽: 셸 경로 `BITPUNK:~/메뉴/화면>` — 화면 아래 메뉴들과 현재 제목, 넘치면 왼쪽을 `..`로 줄임. 오른쪽: TEST ONLY(호박색 채움), SD(테두리), 네트워크(메인넷 호박색 테두리, 테스트넷 흐린 테두리), 에어갭 표시(통신 칩이면 적색) |
| 키 막대 (`hint_bar`, 행 19) | 키는 반전 키 모양, 그 화면에서 실제로 되는 키만. Enter(주 동작)는 신호색 |
| 목록 (`list`, `menu_list`) | 항목당 2행, `>[n]` 번호(1–9는 숫자 키로 바로), 선택은 전체 폭 반전 막대 |
| 로그 줄 (`log_line`, `Tag`) | `[ OK ]` `[ i  ]` `[WARN]` `[FAIL]` `[ -- ]` + 내용 + 오른쪽 세부. 태그는 언어와 무관한 ASCII |
| 경고 3단계 (`message_at`) | 정보: 표시 없음 · 주의: 제목에 `[!]`, 호박색 · 위험: 제목에 `[!!!]`, 적색, 이중 적색 테두리 상자 |
| 표 (`table_row`) | 칸 단위 고정 폭 열, 왼쪽/오른쪽 맞춤 |
| 단어 입력 확인 (`typed_field`, `typed.rs`) | 되돌릴 수 없는 동작만: 카드 포맷 `FORMAT`, 시드 지우기 `WIPE`. 대소문자 무관, 숫자 무시, 틀린 단어는 아무것도 바꾸지 않음, Esc(또는 빈 칸에서 Del)는 취소. 큰 글씨로 입력 내용과 커서 |
| 부팅 자가 점검 (M9-5) | 비 띠 위 이름, 아래로 실제 검사 결과만 로그 줄로(통신 칩 MDIO, 펌웨어 빌드, SD, 시드, 시뮬레이터면 경고). 하지 않는 검사를 OK로 적지 않는다 |
| 화면 보호 (M9-5) | 설정한 시간(1분·5분·끔) 입력이 없으면 비가 화면 전체를 덮는다. 깨우는 키는 다른 동작을 하지 않는다. 비밀 화면(단어·SeedQR·BIP-85 결과·옮겨 적기)은 닫히고, 입력 중인 흐름은 그대로 남는다. 비밀 아닌 QR·카메라·SD 작업·부팅·잠금 중에는 켜지지 않는다 |
| 긴 탐색 | 주소 탐색 중 화면 아래 3행에 비 띠(정보 없는 곳) |
| 모서리 | 모두 직각(터미널) |
| 오류 코드 (`errors.rs`) | 거부·실패 화면은 키 막대 오른쪽에 `E-영역-번호`(예: `E-CARD-03`). 번호는 그 영역 메시지 표의 순서(01부터). 영역 11개: CARD SAVE TX SIGN WAL KEY MSG ADR SIG SET HW. 전체 목록 [ERROR_CODES.md](ERROR_CODES.md)는 시험이 메시지 표에서 만든다 — 메시지를 바꾸면 다시 기록. 새 오류 화면은 `show_error`로 코드를 단다 |

## 6. 효과·비 (확정, M9-2) — `bp_ui::fx`, `bp_ui::rain`

| 단계 (설정 > 화면 효과) | 주사선(홀수 줄 어둡게) | 글로(글자 둘레 번짐) |
|---|---|---|
| 전체 | 25% | 강하게 (알파 1/4) |
| **약하게 (기본)** | 12% | 약하게 (알파 1/9) |
| 끔 | 없음 | 없음 |

- 효과는 앱이 아니라 **화면을 받는 쪽**(시뮬레이터, 실기기 표시 계층)이 입힌다: `FxCanvas::new(fb, settings.fx)` → `app.render` → `finish(app.qr_area())`. 앱의 그림·출력은 효과와 무관하다.
- 글로는 글꼴의 안티에일리어싱 픽셀에만 붙는다. 사각형(판·QR 모듈)은 번지지 않는다.
- **QR 상자는 주사선도 받지 않는다** (`App::qr_area`). 효과 "전체"에서 모든 QR 화면이 우리 스캐너로 읽힘을 시험한다 — `qr_codes_read_through_screen_effects`.
- 설정은 기기 전용: 설정 QR·설정 파일에 들어가지 않는다.
- 계획과 다른 점: "약하게"에서도 모든 글자에 아주 약한 글로(제목만이 아님, 글꼴별 구분 없이 단순하게). 화면 전환 잔광은 화면 내용을 다시 읽어야 해서 넣지 않았다(실기기 표시 계층에서 H2에 검토).
- 실기기: 주사선은 LTDC 두 번째 층의 정지 이미지로 옮길 수 있다(H2).

**매트릭스 비** (`bp_ui::rain::Rain`)
- 64열, 글자는 bech32 글자집합 `qpzry9x8gf2tvdw0s3jn54khce6mua7l`, 머리 글자가 가장 밝고 꼬리는 `LINE` 쪽으로 흐려진다. 60 ms마다 한 걸음.
- 무작위성은 상수로 시작하는 화면 전용 xorshift — 시드 재료와 완전히 분리(시드는 주사위·동전만).
- 쓰는 곳: 부팅·화면 보호·긴 계산 중(M9-5). 정보가 있는 화면에는 쓰지 않는다.
