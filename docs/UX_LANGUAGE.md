# Bitpunk UX 언어 — "Bitpunk Phosphor" (v0.1, M9 진행 중)

이 문서는 **규범**이다. M9에서 확정되며, 이후 모든 마일스톤(M10 보안 저장의 PIN·잠금 화면, M11 백업 도구, M12 업데이트 화면, M13 기능, M14 가이드)이 따른다.
새 부품이나 규칙이 필요하면 먼저 이 문서의 변경을 제안하고 승인받은 뒤 쓴다. (로드맵 원칙 7)
근거: [M9_PLAN.md](milestones/M9_PLAN.md), 목업 캔버스 "Bitpunk Phosphor UI".

장마다 확정된 단위를 적는다. 아직 "예정"인 장은 해당 단위에서 채운다.

## 0. 원칙 (확정, M9 계획)

1. **기능 보존이 최우선.** 모양·위치·조작만 바뀌고 계산·검증·출력은 바이트 단위로 같다. ([기능 대장](FEATURE_INVENTORY.md))
2. **밝기가 곧 중요도.** 녹색 하나의 밝기로 위계를 만든다. 호박색은 주의, 적색은 위험에만.
3. **보이지 않던 검사를 보여 준다.** 기기가 확인한 것을 로그 줄(`[ OK ]` …)로.
4. **정보가 있는 곳에는 비를 내리지 않는다.** 비는 부팅·화면 보호·긴 계산 중에만.
5. **QR은 효과 밖.** 밝은 판 위 검은 모듈, 조용한 여백 4모듈.
6. **색만으로 구분하지 않는다.** 모든 상태에 기호가 함께 있다.
7. **움직임은 최소.** 깜빡임은 커서 1 Hz뿐.
8. **한 키, 같은 자리.** 같은 키는 어디서나 같은 뜻, 키 막대는 늘 맨 아래.
9. **주소는 4자씩 같은 밝기로.** 앞뒤만 강조하지 않는다(주소 중독 공격).

### 4-1. 확인 화면의 틀 (확정, M9-6) — 검토 화면에서 시작해 이후 확인 화면이 따른다

확인할 데이터를 보여 주는 화면은 세 덩어리로 짓는다. 위에서부터 중요한 순서.

| 덩어리 | 행 | 규칙 |
|---|---|---|
| 머리말 | 2–5 | 행 2: 무엇인지(흐림) + 오른쪽 끝에 **다른 단위로 같은 금액**(`= 0.00 060 000 BTC`). 행 3–4: 값을 `DOUBLE`로 `BRIGHT`(주의 조건이면 `WARN`). 행 5: 딸린 값 한 줄(예: 수수료 `금액 \| sat/vB \| %`) |
| 장부 | 다음 행부터 | `table_row` 한 줄에 하나: 이름(흐림, 36칸) · 값(오른쪽 맞춤, 28칸). 들어온 것 = 나간 것 + 수수료가 한눈에 맞도록 모든 줄을 보인다. 우리 것이 아닌 금액은 `TEXT`, 우리 금액은 `BRIGHT` |
| 검증 로그 | 장부 아래 | 기기가 **실제로 확인한 것만** `log_line`으로. 이미 확인한 경고는 `[WARN]` + 제목 + 위치, 자리가 모자라면 마지막 줄이 "경고 n개 더" |

- 덩어리 사이는 빈 행 가운데의 가는 선. 줄이 모자라면(멀티시그 + 외부 입력 등) 빈 행 없이 붙이고, 그래도 넘치면 경고를 접는다 — 화면 밖으로 그리지 않는다.
- 검토 개요의 로그: (멀티시그) 지갑·서명 현황 → 입력 n/m개가 이 시드의 것(키 재유도, 지문) → 내게 돌아오는 출력(주소 재유도) → 서명 해시 ALL → 경고(없으면 "경고 없음").
- 출력 화면: 행 2 "출력 1/2" + 종류(신호색), 금액 `DOUBLE`, 주소는 `TITLE` 4자 묶음 8개씩 **모두 `BRIGHT`**(규칙 9), 우리 출력은 경로 + `[ OK ]` 재유도 확인, 받는 사람 출력은 `[ i  ]` "모든 묶음을 대조".
- 수수료 화면: 머리말에 수수료, 장부에 수수료율·출력 대비 비율·크기, 로그에 기준 검사(넘으면 `[WARN]`, 아니면 `[ OK ]` 설정한 기준), 잠금 시간·RBF는 `[ i  ]`.

### 4-2. 금액 (확정, M9-6, 의도한 변경 C10)

- sats: 세 자리마다 쉼표 `1,234,567 sats`.
- BTC: 소수 여덟 자리를 `2 · 3 · 3`으로 띄어 sats를 바로 읽게 `0.01 234 567 BTC`(정수부는 쉼표). 구분 기호를 빼면 sats 수와 같다.
- 확인 화면 머리말에는 고른 단위로 크게, 다른 단위로 작게 함께 — 단위를 착각해 10배·100배 틀리는 것을 막는다.
- 단위는 설정 > 금액 단위(BTC/sats). 금액은 화면에만 쓰이고 출력(PSBT·파일·QR)에는 영향이 없다.

### 4-3. 시드·키 화면 (확정, M9-7)

- **단어 표** (`word_grid`): 번호는 흐리게, 단어는 **앞 4글자 `BRIGHT` + 나머지 `TEXT`** — BIP-39 단어는 앞 4글자로 구분되고, 입력할 때도 4글자면 완성된다(같은 규칙). 세로로 읽는 순서(1열 위→아래, 다음 열).
- **시드 단어 보기**: 3열, `TITLE` 글자, 24단어는 8행(행 3–18), 12단어는 4행. 행 2 왼쪽에 4글자 규칙, 오른쪽에 화면 보호가 단어를 가릴 때까지 남은 시간(`1:00 뒤 가림`, 10초 이하 호박색, 화면 보호 끔이면 표시 없음). 초가 바뀔 때만 다시 그린다.
- 단어 입력·체크섬 오류 화면의 표는 4열 그대로(화살표 키가 열 수에 맞춰 움직이므로 조작을 바꾸지 않는다).
- **엔트로피 기록판**: 최소 횟수만큼 칸(주사위 50/100칸 20열, D20 30/60칸 10열, 동전 128/256칸 32열 작은 글자)이 채워지고, 빈 칸은 점, 마지막 값은 신호색. 최소를 넘으면 최근 값만(`기록판 - 최근 100개`). 횟수는 `DOUBLE`.
- **지문**: 시드·키가 만들어지거나 불러와지거나 바뀔 때(시드 만듦·불러옴, 스캔한 시드, 패스프레이즈 적용 전, 개인키 불러오기) `DOUBLE` + `BRIGHT`. 마지막 단어 계산 결과도 `DOUBLE`.
- **비밀 데이터**(단어, BIP-85 결과 문자열, 패스프레이즈)는 `BRIGHT` — 확인할 데이터. 경고는 그 앞 화면에서 `[!]`.
- 요약 화면(엔트로피 수락)은 왼쪽 정렬 보고서: 제목 → `[ OK ]` 결과 한 줄 → SHA-256(`BRIGHT`) → 기록한 값.

### 4-4. 목록·파일·주소 (확정, M9-8)

- **디렉터리 목록** (`dir_list`, SD 파일·서명할 PSBT): 행 2에 볼륨(`Volume FAT16  16.6 MB`)과 지금 폴더(`\d1\d2`), 한 행에 한 항목, 폴더는 밝게 + `<DIR>`, 파일은 오른쪽에 크기. 맨 아래 합계 줄(`8 file(s)  179 B   2 folder(s)`)과 범위·숨김 수. 숫자 키가 고르는 목록에만 `[1]`–`[9]`(PSBT 목록), 파일 목록은 번호 없음(위·아래·Enter만).
- 파일 종류는 목록에서 정하지 않는다 — 목록을 그릴 때 파일을 읽지 않기 때문. 파일을 열면 내용으로 판별하고 "이름이 아니라 내용으로 판별했습니다"를 함께 적는다. (계획의 `<PSBT>` `<지갑>` 태그는 모든 파일을 읽어야 해서 넣지 않았다.)
- **카드 상태**: 확인 결과를 로그 줄로(`[ OK ] FAT16 - 16.6 MB` + 클러스터·루트 항목, 문제는 `[WARN]`, 읽는 중 `[ -- ]`). 저장 결과도 `[ OK ] 파일: …`, `[ i  ] 카드를 빼도 됩니다`.
- **주소 목록**: 한 행에 하나, 번호 흐리게, 주소는 4자 묶음(`groups4`), 길면(Taproot) 작은 글자. 선택은 모든 목록과 같은 반전 막대 + `>`.
- 짧은 선택지 목록(지갑 등록 요약·만들기 확인 등)도 공통 목록(`list_rows`, 36px 행) — `>[n]` 번호와 반전 막대가 어디서나 같다.
- 지갑 코드·공동서명자 지문은 `DOUBLE` + `BRIGHT`, xpub 4자 묶음과 메시지 서명·검증된 주소는 `BRIGHT`.

## 5. 조작 (확정, M9-3·M9-4·M9-9)

| 키 | 뜻 (모든 화면 공통) |
|---|---|
| 숫자 | 번호가 붙은 줄을 바로 고름 (입력 화면에서는 입력) |
| Enter | 주 동작 (키 막대에서 신호색) |
| Esc | 뒤로 / 취소 — 비밀 화면에서는 화면을 지우고 나감 |
| ↑↓ / ←→ | 이동 / 값 바꾸기 |
| S | SD에 저장 (카드가 있을 때만 키 막대에 보임) |
| `?` | 이 화면 도움말 (C11). 아무 키나 누르면 닫히고 그 키는 다른 일을 하지 않는다. 글자를 입력하는 화면(패스프레이즈·메시지·서명 확인 메시지)에서는 `?`가 글자이고, 호스트 키보드의 F1만 도움말을 연다. 시작·전원 꺼짐·통신 칩 잠금 화면에는 없다 |
| Fn+Q | QR 스캔 (어느 메뉴에서나) |
| Del | 지우기·되돌리기 |

- **키 막대는 그 화면에서 실제로 되는 키만.** `? 도움말`은 앱이 키 막대 오른쪽 끝에 붙이는데, 키 막대의 내용을 재서(`KeyBarProbe`) 겹치지 않을 때만 그린다. 오류 코드가 있으면 그 왼쪽.
- **도움말 상자**(`view::draw_help`): 행 2–16에 신호색 테두리, `[?] 제목` + 짧은 문단 2~4개 + "아무 키나 누르면 닫힙니다". 주제는 화면 종류별 18개(`help::topic`, 새 화면은 컴파일러가 주제를 정하게 한다). 문단이 상자에 다 들어가는지 영·한으로 시험한다(`help_topics_fit_in_both_languages`).
- **확인 기준:** 되돌릴 수 없는 동작(카드 포맷, 시드 지우기)만 단어 입력(`FORMAT`, `WIPE`). 그 밖의 확인은 한 번, 서명의 기본 선택은 취소.
- **과제 효율:** 핵심 과제의 키 입력·화면 수를 M8과 비교해 늘지 않게 한다(`taskcount.rs`, [비교표](M9_TASKS.md)). 늘어나는 것은 의도한 변경으로 이름을 붙여 허용한다.

## 6. 효과·비 (확정, M9-2) — `bp_ui::fx`, `bp_ui::rain`

| 단계 (설정 > 화면 효과) | 주사선(홀수 줄 어둡게) | 글로(글자 둘레 번짐) |
|---|---|---|
| 전체 | 25% | 강하게 (알파 1/4) |
| **약하게 (기본)** | 12% | 약하게 (알파 1/9) |
| 끔 | 없음 | 없음 |

- 효과는 앱이 아니라 **화면을 받는 쪽**(시뮬레이터, 실기기 표시 계층)이 입힌다: `FxCanvas::new(fb, settings.fx)` → `app.render` → `finish(app.qr_area())`. 앱의 그림·출력은 효과와 무관하다.
- 글로는 글꼴의 안티에일리어싱 픽셀에만 붙는다. 사각형(판·QR 모듈)은 번지지 않는다.
- **QR 상자는 주사선도 받지 않는다** (`App::qr_area`). 효과 "전체"에서 모든 QR 화면이 우리 스캐너로 읽힘을 시험한다 — `qr_codes_read_through_screen_effects`.
- 설정은 기기 전용: 설정 QR·설정 파일에 들어가지 않는다.
- 계획과 다른 점: "약하게"에서도 모든 글자에 아주 약한 글로(제목만이 아님, 글꼴별 구분 없이 단순하게). 화면 전환 잔광은 화면 내용을 다시 읽어야 해서 넣지 않았다(실기기 표시 계층에서 H2에 검토).
- 실기기: 주사선은 LTDC 두 번째 층의 정지 이미지로 옮길 수 있다(H2).

**매트릭스 비** (`bp_ui::rain::Rain`)
- 64열, 글자는 bech32 글자집합 `qpzry9x8gf2tvdw0s3jn54khce6mua7l`, 머리 글자가 가장 밝고 꼬리는 `LINE` 쪽으로 흐려진다. 60 ms마다 한 걸음.
- 무작위성은 상수로 시작하는 화면 전용 xorshift — 시드 재료와 완전히 분리(시드는 주사위·동전만).
- 쓰는 곳: 부팅·화면 보호·긴 계산 중(M9-5). 정보가 있는 화면에는 쓰지 않는다.
