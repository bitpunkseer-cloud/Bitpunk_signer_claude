# Bitpunk UX 언어 — "Bitpunk Phosphor" (v0.1, M9 진행 중)

이 문서는 **규범**이다. M9에서 확정되며, 이후 모든 마일스톤(M10 보안 저장의 PIN·잠금 화면, M11 백업 도구, M12 업데이트 화면, M13 기능, M14 가이드)이 따른다.
새 부품이나 규칙이 필요하면 먼저 이 문서의 변경을 제안하고 승인받은 뒤 쓴다. (로드맵 원칙 7)
근거: [M9_PLAN.md](milestones/M9_PLAN.md), 목업 캔버스 "Bitpunk Phosphor UI".

장마다 확정된 단위를 적는다. 아직 "예정"인 장은 해당 단위에서 채운다.

## 0. 원칙 (확정, M9 계획)

1. **기능 보존이 최우선.** 모양·위치·조작만 바뀌고 계산·검증·출력은 바이트 단위로 같다. ([기능 대장](FEATURE_INVENTORY.md))
2. **밝기가 곧 중요도.** 녹색 하나의 밝기로 위계를 만든다. 호박색은 주의, 적색은 위험에만.
3. **보이지 않던 검사를 보여 준다.** 기기가 확인한 것을 로그 줄(`[ OK ]` …)로.
4. **정보가 있는 곳에는 비를 내리지 않는다.** 비는 부팅·화면 보호·긴 계산 중에만.
5. **QR은 효과 밖.** 밝은 판 위 검은 모듈, 조용한 여백 4모듈.
6. **색만으로 구분하지 않는다.** 모든 상태에 기호가 함께 있다.
7. **움직임은 최소.** 깜빡임은 커서 1 Hz뿐.
8. **한 키, 같은 자리.** 같은 키는 어디서나 같은 뜻, 키 막대는 늘 맨 아래.
9. **주소는 4자씩 같은 밝기로.** 앞뒤만 강조하지 않는다(주소 중독 공격).

**규칙 (시험으로 강제)**
- 화면 코드는 색을 이 토큰으로만 쓴다. 다른 곳에 색 값을 쓰면 그 줄에 `// palette: 이유`를 단다(예: 카메라 그림). — `screens_use_theme_colours_only`
- 글자 색은 `BG`·`SURFACE`·`SURFACE_HI` 위에서 본문·데이터 7:1, 보조 4.5:1 이상, 반전 글자는 4.5:1 이상. — `bp_ui::theme::tests::text_colours_are_readable`
- 상태줄: 메인넷 배지는 호박색 테두리, 테스트넷은 흐린 테두리, TEST ONLY는 호박색 채움.

## 2. 격자 (확정, M9-1) — `bp_ui::grid`

- 800×480 = **64열 × 20행**, 칸 12×24 px, 좌우 여백 16 px. ASCII 1칸, 한글 2칸.
- 행 0 상태줄 · 행 1 구분선 · 행 2–17 내용(16줄) · 행 18 구분선 · 행 19 키 막대.
- 위치는 `grid::x(col)`, `grid::y(row)`, 글자는 `grid::text_y(font, row, rows)`로 칸 안에 놓는다. 구분선 `grid::rule(row)`, 상자 `grid::frame(..., double)`(위험 상자는 이중선).
- (M9-3부터 공통 부품이 이 격자 위에 그려지며, 화면 순회가 칸 맞춤을 검사한다.)

## 3. 글자 (확정, M9-1) — `bp_ui::font`

| 글꼴 | 크기 | 칸 | 쓰임 |
|---|---|---|---|
| `BODY` | JetBrains Mono 20 px, 한글 Noto Sans KR | 1칸 × 1행 | 본문 전부 |
| `SMALL` | 15 px | — | 배지·키 막대 글자 |
| `TITLE` | 28 px (한글 있음) | — | 한글이 든 제목 |
| `DOUBLE` | JetBrains Mono ExtraBold 40 px, ASCII만 | 2칸 × 2행 | 금액·지문·ASCII 제목 (VT100 이중 크기 줄처럼) |

- `DOUBLE`에는 한글이 없다. 한글 제목은 `TITLE`.
- 글꼴은 모두 SIL OFL 1.1, 생성 도구 `tools/gen_font.py`(`DOUBLE`은 이름을 주어 따로 생성), `tools/gen_hangul.py`.

## 4. 공통 부품 (예정, M9-3)
상태줄(경로·보안 상태), 키 막대, 번호 메뉴·반전 선택, 표·페이지, 로그 목록(태그), 경고 3단계 상자, 단어 입력 확인, 오류 코드.

## 5. 조작 (예정, M9-3·M9-4)
키의 공통 뜻, 키 막대 규칙, 확인 기준, 메뉴 구조.

## 6. 효과·비 (예정, M9-2)
효과 3단계(전체·약하게·끔), 주사선·글로·잔광·커서, QR 제외, 매트릭스 비(bech32 글자, 화면용 의사난수 — 시드 재료와 분리).

## 7. 문구 (예정, M9-9)
영·한 문구 규칙, 오류 메시지 형식(무엇이 문제인지 + 다음에 할 일 + 코드).

## 8. 새 화면 점검표 (예정, M9-10)
새 화면을 만들 때 확인할 항목. 화면 전수 검사(`coverage.rs`)에 등록하지 않으면 컴파일되지 않는다.
