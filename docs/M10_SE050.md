# SE050 드라이버 (M10-8)

보관함의 보안 칩(결정 1, NXP SE050, OM-SE050ARD-E 실드)을 쓰는 드라이버 `crates/bp-se050`의 설계와 검증 현황. 실기기 연결은 H 트랙에서 한다. 그 전까지 모든 바이트는 **참조 구현·공개 시험 벡터·모의 칩**으로 검사한다.

## 1. 계층

| 모듈 | 내용 | 근거 |
|---|---|---|
| `crc` | CRC-16/X.25 (T=1 프레임 끝) | 카탈로그 검사값 `0x906E`, 참조 드라이버의 CRC와 300개 무작위 입력 비교 |
| `t1` | T=1 over I2C (UM11225): 블록(I/R/S), 연결(chaining), WTX, RESYNC, 소프트 리셋과 ATR 타이밍, 재전송 | PCB 부호화를 참조 드라이버와 비교 |
| `apdu` | ISO 7816-4 명령(짧은·확장 길이), BER-TLV | 왕복 시험, 참조 드라이버의 `iso7816` 규칙(답 길이 "최대"면 확장 길이) |
| `scp03` | GlobalPlatform SCP03 (Amendment D, S8): 세션 키, 카드/호스트 암호문, C-MAC+C-ENC, R-MAC+R-ENC, PUT KEY | 독립 구현의 공개 기지값(KAT, GP 기본 키 40..4F): 암호문, EXTERNAL AUTHENTICATE, 데이터 명령 포장, 응답 풀기, PUT KEY 키 암호화가 바이트 단위로 같음 |
| `cmd` | 보관함이 쓰는 SE05x 명령 15개 | 참조 드라이버(`se05x` 0.4.2, Nitrokey)가 만드는 APDU와 바이트 단위로 같음 (속성 읽기만 Le를 붙임) |
| `device` | `Se050`: 보관함의 `SecureElement` | 모의 칩 위 종단 시험, 보관함(`vault.rs`) 전체 시험 |
| `mock` | I2C 수준 모의 SE050 (기능 `mock`, 시험·시뮬레이터 전용) | — |

참조 드라이버는 LGPL-3.0이라 **시험에서만** 쓰고 펌웨어에는 넣지 않는다. AES-128과 AES-CMAC는 `bp-crypto/src/aes.rs`(새 파일)에 독자 구현했다. S-박스 조회는 표 전체를 읽고 마스크로 고르므로 캐시 타이밍으로 키가 새지 않는다(FIPS-197, RFC 4493 벡터, RustCrypto 교차 검사).

## 2. 칩 안의 객체

| 객체 | ID | 종류 | 권한(정책) |
|---|---|---|---|
| AUTH | `7B100001` | UserID, A의 앞 16바이트, 최대 시도 10 | 자기 세션만 고쳐 쓰기, 누구나 지우기 |
| SECRET | `7B100002` | 바이너리 32바이트 = S, **칩의 난수 발생기**로 만듦 | AUTH로 인증한 세션만 읽기, 누구나 지우기 |
| HMAC | `7B100003` | HMAC 키 32바이트 (칩의 난수) | 누구나 MAC 계산, 읽기·지우기 불가 |
| COUNTER | `7B100004` | 카운터 8바이트 | 읽기와 1 더하기, 지우기 불가 |

- PIN이 틀리면 칩이 시도를 센다. 10번이면 UserID가 영구히 잠겨 SECRET을 다시는 읽을 수 없다. 펌웨어가 세는 것이 아니다.
- 보관함 지우기(`destroy`)는 SECRET과 AUTH만 지운다. HMAC 키(확인 단어·탬퍼 점검)와 카운터(롤백 방지)는 남는다.
- 프로비저닝 순서는 SECRET → AUTH. AUTH가 생기기 전에는 칩이 "비어 있음"으로 보인다. 도중에 전원이 끊기면 남은 SECRET은 다음 프로비저닝 때 지운다(모든 APDU 지점 전원 끊김 시험).

## 3. 채널: Platform SCP03

- 모든 명령을 SCP03 보안 수준 `0x33`(명령 MAC·암호화, 응답 MAC·암호화)으로 감싼다. I2C 선을 엿들어도 A(인증값)와 S(비밀)는 보이지 않는다. 시험 `nothing_secret_crosses_the_bus_in_the_clear`가 버스에 오간 모든 바이트에서 A와 S를 찾아 없음을 확인한다.
- 우리 키를 모르는 칩(바꿔치기한 칩)은 카드 암호문이 맞지 않아 연결 단계에서 거부된다.
- 응답 MAC이 틀리거나 빠지면 채널을 버리고, 다음 명령에서 새로 연다.

### 키 관리 (H 트랙에서 실기기로 확정)

1. SE050은 변종별로 **공개된 기본 Platform SCP 키**를 갖고 나온다. 그대로 쓰면 엿듣는 사람도 풀 수 있다.
2. 첫 부팅에 기본 키로 연결한 뒤, 기기 고유 난수 키로 **PUT KEY 교체**(`Se050::rotate_keys`, KCV 확인)를 한다. 새 키는 기기 키(SAES DHUK)로 감싸 플래시에 둔다.
3. 칩에 "Platform SCP 필수"를 설정해, SCP 없는 명령은 칩이 거부하게 한다(모의 칩은 기본으로 거부).
4. 시뮬레이터는 페이지마다 다른 키를 쓴다(실기기의 교체 후 상태와 같음).

## 4. 시뮬레이터

웹 시뮬레이터의 보관함은 M10-8부터 이 드라이버를 그대로 쓴다. T=1, SCP03, APDU가 모두 브라우저에서 돌고, 칩만 모의다. 만들기 약 0.13초, 잠금 해제 약 0.07초다(Argon2id 포함, 브라우저 측정).

## 5. 실기기에서 확인할 것 (H 트랙 점검표)

| # | 항목 | 지금 가정 |
|---|---|---|
| H-1 | 실드 연결: I2C 주소 0x48, CardKB와 같은 버스, 전원·리셋 핀 | 주소 0x48 |
| H-2 | ATR의 BWT·MPOT·SEGT, 첫 RESYNC가 필요한지 | ATR 값을 읽어 씀 |
| H-3 | Platform SCP03을 애플릿 선택 뒤 바로 여는 순서, 확장 길이 APDU를 SCP로 감쌀 때의 Lc | 짧은 APDU 우선, 확장은 3바이트 Lc |
| H-4 | 성공한 UserID 인증이 실패 횟수를 0으로 되돌리는지 | 되돌림(보관함 규칙과 같음) |
| H-5 | 세션 안에서 UserID 값 바꾸기 허용 여부 | 자기 세션에서 허용 |
| H-6 | 정책 의미(목록에 없는 세션은 권한 없음), 기본 세션 ID `00000000` | 그렇게 가정 |
| H-7 | PUT KEY로 Platform SCP 키 교체(키 ID 1~3, 버전), 교체 후 기본 키 거부 | GP 표준대로 |
| H-8 | "Platform SCP 필수" 설정 명령 | 미구현(H 트랙) |
| H-9 | 응답 오류 상태에 R-MAC이 붙는지 | 오류 상태는 MAC 없이도 받음, 9000은 MAC 필수 |

## 6. 시험

- `bp-se050`: 15개 — CRC, PCB, APDU·TLV, SCP03 기지값, 명령 15개 바이트 비교, 종단(보관함 규칙, 버스 평문 없음, 바쁜 칩·손상 프레임·WTX·긴 명령/응답 연결, 잘못된 키·SCP 없는 명령 거부, 키 교체, 프로비저닝 중 모든 지점 전원 끊김).
- `bp-app`: 보관함 전체를 드라이버+모의 칩 위에서(만들기·저장·틀린 PIN·속임수 PIN·PIN 바꾸기·10회 잠김), 저장 중 모든 APDU 지점 전원 끊김.
- 시뮬레이터 E2E: 보관함 단계 전부가 드라이버 위에서 통과.
