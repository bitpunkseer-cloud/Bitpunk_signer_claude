# Bitpunk Signer — 하드웨어 및 운영 요구사항

> 최종 목표: QWERTY 물리 키보드를 가진 휴대용 기기(아래 폼팩터 참조)에
> DIY 서명 펌웨어/소프트웨어를 이식한다.

## 1. 폼팩터
- 상단 디스플레이 + 하단 물리 키보드. 입력은 **키보드 우선 UX**, 터치는 선택 사항.
- 키보드는 PC형(Ctrl/Alt/F키 포함)이 아니라 **Coldcard Q처럼 서명기에 필요한 키만** 둔다 (2026-11-20 결정).

### 1.1 키 배열 — M5Stack CardKB v1.1 (50키, 2026-11-20 결정)

시중에서 무선 칩 없이 바로 살 수 있는 모듈로 확인된 것이 CardKB v1.1이므로, 시뮬레이터와 펌웨어 키 처리를 **CardKB v1.1 실물 배열**에 맞춘다.
(배열 근거: CardKB ATmega8a 펌웨어의 `KeyMap` 표와 기판 사진. 방향키 4개의 정확한 좌표는 사진에서 추정)

```
          [Esc][1][2][3][4][5][6][7][8][9][0][Del]
  [MCU]   [Tab][Q][W][E][R][T][Y][U][I][O][P][Fn ]
               [Shift][A][S][D][F][G][H][J][K][L][Enter]
     ▲         [Sym  ][Z][X][C][V][B][N][M][,][.][Space]
   ◄   ►
     ▼
```

| 층 | 동작 |
|---|---|
| Shift | 한 번 = 다음 글자 대문자, 두 번 = 대문자 고정 (숫자는 그대로) |
| Sym | 1~0 → `! @ # $ % ^ & * ( )`, Q~P → `{ } [ ] / \ | ~ ' "`, A~K → `; : ` + - _ = ?`, `,` → `<`, `.` → `>` |
| Fn | 우리 펌웨어에서 정의. **Fn+Q = QR 스캐너** |

- Sym 층과 기본 키로 출력 가능한 ASCII 기호 32개를 모두 입력할 수 있음 → 패스프레이즈 제약 없음.
- 펌웨어 출력 코드(참고): Esc 27, Del 8, Tab 9, Enter 13, ◄ 0xB4, ▲ 0xB5, ▼ 0xB6, ► 0xB7.

### 1.2 키보드 하드웨어 추천

| 용도 | 추천 | 근거 |
|---|---|---|
| 선택 사항(나중에) | 직접 설계한 키 매트릭스 PCB를 메인 칩의 GPIO로 직접 스캔 | 키보드 칩이 따로 없어 보안상 가장 좋음. 만들게 되면 CardKB와 같은 배열로 설계해 화면·펌웨어를 그대로 씀 |
| **채택** | **M5Stack CardKB v1.1** (제품 번호 U035-B) | 시판 중. ATMega8A 컨트롤러, I2C(주소 0x5F), 50키 QWERTY, 88×54mm. **무선 칩 없음**. 컨트롤러를 우리 펌웨어로 다시 써 넣을 수 있음(6핀 ISP 패드) |
| ❌ 피할 것 | **CardKB2** (CardKB의 후속 모델) | **BLE(블루투스) 모드가 있음** → HW-1 위반 |
| ❌ 피할 것 | ESP32 계열 컨트롤러를 쓰는 키보드 모듈 | 칩에 Wi-Fi/BLE가 내장 → HW-1 위반 |
| 참고(구하기 어려움) | Solder Party BBQ10/BBQ20 키보드, Keyboard FeatherWing, KeebDeck | BlackBerry 키보드 기반 I2C 모듈은 단종, KeebDeck은 USB 전용·품절. 회로도는 공개돼 있어 최종 PCB 설계 참고용 |

- 키보드 모듈을 쓰는 경우에도 그 컨트롤러 펌웨어는 **우리가 빌드한 것으로 교체**하는 것을 원칙으로 함(H 트랙).

## 2. 절대 요구사항 (MUST)
| ID | 요구사항 |
|---|---|
| HW-1 | **100% 에어갭**: Wi-Fi·Bluetooth·셀룰러·LoRa 등 **무선 통신 모듈이 물리적으로 존재하지 않을 것**. (SoC 다이에 무선이 내장된 칩도 배제: 예 ESP32 계열, Pi Zero W/2W) |
| HW-2 | **NFC 없음** |
| HW-3 | **USB 데이터 연결 없음**. (USB 포트가 있다면 충전 전용, 데이터 라인 물리 차단) |
| HW-4 | **카메라 탑재**: QR 스캔으로 PSBT 서명, 시드/개인키 가져오기, 디스크립터 등록 등 수행 |
| HW-5 | **microSD 슬롯**: 최초 펌웨어 설치와 업데이트는 **SD 카드로만** 수행 |
| HW-6 | 데이터 출력 경로는 **화면 QR 표시**와 **SD 카드** 두 가지뿐 |

## 3. 개발/검증 프로세스 요구사항
- 매 개발 빌드마다 변경사항을 GitHub에 커밋·푸시.
- 빌드 결과물을 **실제 하드웨어 화면과 동일하게 생긴 웹 시뮬레이터**로 제공하고, 링크로 열어 검증·테스트 가능해야 함
  (모바일 앱 내 브라우저에서도 동작).
- **구현 전에 항상 구현 방향을 먼저 제시 → 승인 후 구현.**

## 4. 소프트웨어 원칙
- 언어: **Rust**.
- `embit`, `libwally-core` 등 기존 비트코인 라이브러리에 의존하지 않는 **독자 코드/라이브러리**.
- 표준 사양(BIP/BCR)과 공식 테스트 벡터로 검증.
