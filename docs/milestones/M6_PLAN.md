# M6 구현 계획 — 서명 확장 · 한국어 UI

상태: **제안 (승인 대기)**

## 1. 목표

M5까지 만든 서명·QR 엔진 위에 **"받기 전에 주소 확인"**, **"메시지 서명"**, **설정**, **한국어 화면**을 얹는다.

**완료 기준**
- Sparrow의 "Sign by QR"(Electrum 형식)와 "BIP322 (Simple)" QR 요청을 Bitpunk가 서명하고, Sparrow가 그 서명을 검증함
- Sparrow 수신 탭의 주소를 스캔하면 Bitpunk가 그 주소의 경로(계정·수신/거스름·번호)를 찾아 보여 줌
- 모든 화면이 한국어로 나오고, 쓰인 한글 글자가 모두 글꼴에 들어 있음을 CI가 확인
- 같은 D20 주사위 값에서 Krux와 같은 엔트로피가 나옴, SettingsQR 내보내기 → 다시 읽기 왕복

## 2. 범위

| 포함 | 나중 |
|---|---|
| 한국어 UI 전체 + 언어 설정 | 한글 입력(패스프레이즈 등)은 계획 없음 (BIP-39·패스프레이즈는 ASCII) |
| QR 주소 검증 (단일 서명 4종) | 멀티시그 주소 → M7 |
| 메시지 서명: `signmessage` QR(Electrum 형식), BIP-322 PSBT(P2WPKH·P2TR) | BIP-322 Proof of Funds(입력 여러 개), 메시지 서명 검증 → 나중 (5장 결정 3) |
| 설정: 수수료 경고·차단선, 메시지 서명 켜기/끄기, SettingsQR 내보내기/읽기 | 설정 저장(전원 꺼도 유지) → M9 보안 저장 |
| D20 주사위 | — |
| (M3·M4에서 이미 끝남) BBQr·Specter 형식 | — |

## 3. 조사 결과 (레퍼런스에서 확인한 것)

| 항목 | 확인한 사실 | Bitpunk 적용 |
|---|---|---|
| 메시지 서명 QR 형식 | SeedSigner와 Sparrow 모두 `signmessage <경로> ascii:<메시지>` 한 장짜리 QR. SeedSigner는 `ascii:` 외 형식은 거부 | 같은 형식 지원 |
| 서명 형식 | SeedSigner: 헤더 27+4+recid(**Electrum 형식**, 주소 종류와 무관하게 31~34). Sparrow "Standard (Electrum)"도 같고, 탭루트에서는 Electrum 형식을 끔 | Electrum 형식. 탭루트는 BIP-322로만 |
| 경로 제한 | SeedSigner: 표준 단일 서명 경로(44/49/84/86, 코인 0/1)만, 사용자 정의 경로는 거부, **네트워크가 다르면 거부**. 서명 전에 메시지(여러 쪽)와 그 경로의 주소를 보여 줌 | 같은 규칙 + 마지막 확인은 기본 "취소" |
| BIP-322 QR 흐름 | Sparrow "BIP322 (Simple)"은 `to_sign` 가상 거래를 PSBT(UR `crypto-psbt` 또는 BBQr)로 보냄. 메시지 원문은 전역 키 `0x09`(`PSBT_GLOBAL_GENERIC_SIGNED_MESSAGE`)에 들어 있음 | 같은 흐름 |
| BIP-322 서명기 규칙 | BIP-322 본문에 서명기 절차가 있음: 전역 `0x09` 메시지와 첫 입력의 scriptPubKey로 `to_spend`를 **다시 만들어 txid가 입력과 같은지**, 출력이 값 0의 `OP_RETURN` 하나인지 확인. 맞으면 "거래"가 아니라 **"이 주소로 이 메시지에 서명"** 화면을 보여야 함 | 규칙 그대로. 재계산이 맞아야만 메시지 화면으로 가고, 메시지와 주소는 `Verified<T>` |
| 시험 벡터 | BIP-322 `basic-test-vectors.json`(메시지 해시·거래 해시·simple), `generated-test-vectors.json`(simple·full·PoF·오류) | 전부 시험에 사용 |
| 주소 검증 | SeedSigner: 주소 형식으로 스크립트 종류를 정하고, 계정 0의 수신·거스름을 번갈아 0번부터 찾을 때까지 계산(사용자가 멈출 수 있음). P2WSH·P2SH는 멀티시그 가능성 처리 | 같은 방식 + 불러온 시드 전부, 다른 계정도 선택 가능 |
| D20 | Krux: 값을 `-`로 이어 붙인 문자열의 SHA-256, 최소 30회(12단어)·60회(24단어) | Krux와 같게 (D6는 이미 같음) |
| SettingsQR | SeedSigner: `settings::v1 이름=값 …`, 모르는 항목은 무시, 값 검증 | 같은 문법, 접두어는 우리 것 (결정 5) |

## 4. 설계

### 4.1 한국어 UI
- 글꼴 생성기(`tools/gen_font.py`)가 한국어 문자열 표에서 **실제로 쓰인 한글 글자만 모아** SMALL·BODY·TITLE 크기로 굽는다. HUGE(금액·지문)는 숫자·영문만.
- 한글은 영문 2칸 너비. `text_width`·줄바꿈·가운데 정렬을 칸 단위로 바꾼다.
- CI 시험: 한국어 표의 모든 글자가 글꼴에 있어야 통과. 글꼴에 없는 글자(스캔한 텍스트 등)는 `□`로 표시.
- 설정 > 언어: English / 한국어. BIP-39 단어, 주소, 경로, 지문은 그대로.

### 4.2 QR 주소 검증
- 스캔 결과가 주소면 "이 기기의 주소인지 확인" 선택지. 도구 > 주소 검증도 같은 흐름.
- 주소 형식 → 스크립트 종류(P2PKH=44, P2SH=49(P2SH-P2WPKH로 가정), P2WPKH=84, P2TR=86). P2WSH는 "멀티시그 주소: M7".
- 네트워크가 설정과 다르면 거부.
- 불러온 시드마다 계정 0의 수신·거스름을 0번부터 번갈아 계산. 진행 화면(시드·확인한 개수), Esc로 멈춤. 계정 xpub 하나에서 비강화 파생만 하므로 빠름.
- 찾으면: "확인됨: 시드 73c5da0a · m/84'/0'/0'/0/17 (수신 #17)". 못 찾으면 범위와 함께 "찾지 못함", "더 찾기"·"다른 계정" 선택.

### 4.3 메시지 서명 (Electrum 형식)
- 형식 판별기에 `signmessage` 추가. 경로 규칙: `m/{44|49|84}'/{코인}'/{계정}'/{0|1}/{번호}`, 코인은 네트워크와 일치, 86은 BIP-322로 안내.
- 메시지는 인쇄 가능한 ASCII와 줄바꿈만(결정 2). 화면: 메시지 전체(여러 쪽) → 서명할 주소(시드에서 파생, "확인됨") → 최종 확인(기본 취소).
- 서명: 메시지 해시 `SHA256d("\x18Bitcoin Signed Message:\n" ‖ len ‖ msg)`, ECDSA **복구 가능 서명**(RFC 6979, low-S, 그라인딩 없음 → Bitcoin Core `signmessage`와 바이트 일치), 헤더 31~34, base64.
- 내보내기 전에 서명에서 공개키를 복구해 파생한 키와 같은지 확인, 키 소거. 결과는 한 장짜리 QR(시뮬레이터는 텍스트도).

### 4.4 BIP-322
- PSBT를 받으면 먼저 BIP-322 여부를 규격대로 판정(0x09 메시지, 입력 1개, prevout.n=0, `to_spend` 재계산 txid 일치, 출력이 값 0 `OP_RETURN` 하나). 판정되면 거래 검토 대신 메시지 서명 화면으로 간다.
- 입력의 소유권은 M5 검증기와 같은 재파생 검사(P2WPKH·P2TR 키 경로). 입력이 여러 개(Proof of Funds)면 M6에서는 거부.
- 서명은 M5 파이프라인 그대로(BIP-143 / BIP-341, 서명 검증, 축소본 PSBT, UR·BBQr 출력). Sparrow가 받아서 simple 서명으로 마무리한다.
- `0x09`가 있지만 재계산이 맞지 않으면 **공격**으로 판정(메시지와 서명 대상이 다름).

### 4.5 설정 · SettingsQR
- 서명 안전 설정: 수수료 경고(%), 수수료 차단선(%), 수수료율 경고(sat/vB), 거스름 번호 범위. 허용 범위 안에서만 조정(차단선 끄기 불가). 공격·오류 판정은 설정으로 바꿀 수 없음.
- 메시지 서명 켜기/끄기(결정 4).
- SettingsQR: 현재 설정을 QR로 보여 주고(종이·휴대폰에 보관), 스캔하면 **바뀌는 항목을 보여 주고 확인(기본 취소)** 후 적용. 기기는 M9 전까지 전원을 끄면 설정을 잊으므로 이것이 보관 수단.

### 4.6 D20
- 시드 만들기 > 주사위 D20. 숫자 입력 후 Space/Enter로 한 번 굴림. 1~20 외 값 거부.
- 엔트로피 계산(한 번에 log2 20 ≈ 4.32비트), 최소 30·60회, 치우침·반복·연속 검사를 20면에 맞게 확장.
- 해시 입력: `-`로 이은 값(Krux와 같음). Krux와 같은 값 → 같은 엔트로피 시험.

## 5. 결정 필요

1. **한국어 글꼴**
   - **(권장)** Noto Sans Mono CJK KR (SIL OFL): 고정폭, 작은 크기에서 읽기 쉬움, 한글 디자인이 표준적
   - D2Coding (SIL OFL, 네이버): 코딩용, 지금 영문 글꼴(JetBrains Mono)과 분위기가 비슷
   - Galmuri (SIL OFL): 픽셀 글꼴, 작지만 지금 크기(15~28 px)와 맞지 않음
2. **메시지에 허용할 글자**
   - **(권장)** 인쇄 가능한 ASCII + 줄바꿈만, 그 밖의 글자가 있으면 서명 거부 (보이지 않는 글자·비슷한 글자로 속이는 것 방지, SeedSigner도 ASCII만)
   - UTF-8 허용, 화면에 못 그리는 글자는 `\u{…}`로 표시
3. **메시지 서명 검증(남이 서명한 메시지 확인)**
   - **(권장)** M6에서는 제외 (표준 QR 형식이 없고, 에어갭 기기에서 쓸 일이 적음) → SD 파일 기능(M8)과 함께
   - M6에 포함 (주소·메시지·서명을 붙여넣기/스캔)
4. **메시지 서명 기본값**
   - **(권장)** 켜짐. 대신 매번 메시지 전체·주소를 보여 주고 최종 확인 기본값은 "취소"
   - 꺼짐(SeedSigner처럼 설정에서 켜야 함): "소유권 증명" 사칭 피싱에 더 안전하지만 한 단계 더 필요
5. **SettingsQR 접두어**
   - **(권장)** `bitpunk-settings::v1 …` (SeedSigner와 같은 문법, 다른 접두어 → 서로의 QR을 잘못 읽지 않음)
   - SeedSigner와 같은 `settings::v1`
6. **언어 기본값**
   - **(권장)** English (설정에서 한국어로 바꿈. 국제 기본값)
   - 한국어

## 6. 커밋 단위

1. 글꼴 생성기: 한글 부분 집합 + 2칸 너비 그리기 + 글자 누락 검사
2. 문자열 표 구조(언어 전환) + 한국어 번역 전체 + 화면 배치 조정
3. 주소 검증 엔진(bp-bitcoin) + 화면
4. ECDSA 복구 가능 서명 + Electrum 메시지 서명·복구(bp-crypto/bp-bitcoin) + 벡터
5. `signmessage` 판별 + 메시지 서명 화면 + 결과 QR
6. BIP-322: `to_spend`/`to_sign`, PSBT 판정, 검토 화면, 벡터
7. 서명 안전 설정 + 메시지 서명 켜기/끄기 + SettingsQR
8. D20 주사위
9. 시뮬레이터·문서·배포 + Sparrow 왕복 확인 방법

## 7. 시험

| 대상 | 방법 |
|---|---|
| 한국어 | 모든 화면을 한국어로 그려 패닉·글자 누락 없음, 한 줄 넘침 검사, 스크린숏 확인 |
| 주소 검증 | rust-bitcoin으로 만든 주소(4종, 수신·거스름, 여러 번호·계정·시드)가 맞는 경로로 찾아짐, 남의 주소는 못 찾음, 네트워크 불일치 거부 |
| 메시지 서명 | rust-bitcoin(`sign_message`)·libsecp256k1 복구 서명과 바이트 일치, 공개키 복구 왕복, 경로·네트워크·글자 규칙 |
| BIP-322 | 공식 벡터(메시지 해시, `to_spend`/`to_sign` txid, simple 서명 검증), Sparrow 방식 PSBT 서명 → rust-bitcoin으로 검증, 재계산 불일치 = 공격 |
| D20 | Krux 방식으로 만든 기대값과 같은 엔트로피, 검사 기준 |
| SettingsQR | 내보내기 → 읽기 왕복, 잘못된 값 거부, 바뀌는 항목 확인 화면 |
| 퍼징 | `signmessage`·SettingsQR 파서, BIP-322 판정 |
