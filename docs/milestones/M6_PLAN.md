## 1. 목표

**완료 기준**
- Sparrow "Sign by QR"(Electrum)와 "BIP322 (Simple)" 요청에 Bitpunk가 서명하고 Sparrow가 검증함
- Sparrow 수신 탭의 주소를 스캔하면 Bitpunk가 시드·경로를 찾아 "확인됨"을 보여 줌
- 모든 화면이 한국어로 나오고, 쓰인 한글이 모두 글꼴에 있음을 CI가 확인
- 같은 D20 값에서 Krux와 같은 엔트로피, SettingsQR 왕복

## 3. 메시지 서명

### 3.1 요청
| 경로 | 처리 |
|---|---|
| QR `signmessage <경로> ascii:<메시지>` | Sparrow·SeedSigner·Coldcard·Jade·Krux·Passport와 같은 형식. 경로 앞 지문이 있으면 그 시드를 자동 선택 |
| 기기 입력 | 도구 > 메시지 서명: 키보드로 메시지 입력 → 주소 탐색기에서 주소 선택 |
| 주소 검증 결과 | "이 주소로 메시지 서명" |
| PSBT (BIP-322) | 4장 |

### 3.2 규칙 (어기면 서명 거부, 이유 표시)
- 경로: `m/{44,49,84,86}'/{코인}'/{계정}'/{0,1}/{번호}`만. 코인은 설정 네트워크와 같아야 함. 그 밖은 거부.
- 메시지: 인쇄 가능한 ASCII와 줄바꿈만. 처음·끝 공백 금지, 공백 3개 연속 금지. 2자 이상, 최대 길이는 결정 2.
- `base64:` 등 다른 인코딩, 원시 해시는 받지 않음.

### 3.3 화면
1. **메시지**: 모든 쪽을 넘겨 봐야 다음으로. 줄바꿈은 보이는 기호로 표시. 마지막 쪽에 메시지 해시(SHA-256d).
2. **주소**: 시드에서 파생한 주소(4글자 묶음) + 경로 + 시드 지문, "확인됨".
3. **최종 확인**: "서명" / "취소", 기본 선택 "취소".

### 3.4 서명
- 44/49/84: 메시지 해시 → ECDSA **복구 가능 서명**(RFC 6979, low-S) → Electrum 헤더(31~34) → base64. Bitcoin Core `signmessage`와 바이트 일치.
- 86: BIP-322 simple (Schnorr, 키 트윅, 보조 난수 0) → base64 witness.
- 내보내기 전에 검증(ECDSA는 공개키 복구 후 대조, Schnorr는 출력 키로 검증), 키 소거. 결과는 한 장짜리 QR.

## 4. BIP-322 (PSBT)

- 판정(BIP-322 본문 + CC): 전역 `0x09` 메시지, 출력이 값 0인 `OP_RETURN`(스크립트 `6a`) 하나, 입력 0의 prevout.n = 0, **`to_spend` 재계산 txid = 입력 0의 prevout**, 입력 0 금액 0, non_witness_utxo가 있으면 `to_spend`와 바이트 일치, 거래 버전 0 또는 2.
- `0x09`와 `OP_RETURN` 출력은 있는데 나머지가 맞지 않으면 **공격**(메시지와 실제 서명 대상이 다름).
- 입력 0은 이 시드의 키여야 함(M5 재파생 검증, P2WPKH·P2SH-P2WPKH·P2TR). SIGHASH ALL(탭루트 DEFAULT)만.
- **Proof of Reserves**(입력 2개 이상): 모든 입력이 이 시드 것이어야 함(외부 입력 금지), 금액 합계 표시. UTXO 금액 기억·수수료 검사는 하지 않음(방송할 수 없는 거래).
- 화면: "메시지 서명 (BIP-322)" 또는 "보유 증명 (Proof of Reserves)" + 메시지(3.3과 같은 규칙) + 주소(+ 금액) → 최종 확인(기본 취소).
- 서명·출력은 M5 파이프라인(재검증, 서명 검증, 축소본, UR·BBQr·Specter).

## 5. 메시지 서명 검증

- 입력: armored 형식 QR(`-----BEGIN BITCOIN SIGNED MESSAGE-----` … 주소 … 서명), 또는 주소·메시지·서명을 차례로 스캔/입력.
- Electrum·BIP-137 헤더 모두 검증, 헤더가 주소 종류와 안 맞으면 경고(CC). P2TR·P2WPKH의 BIP-322 simple도 검증.
- 결과: "유효: 주소 X가 이 메시지에 서명함" / "무효". 주소가 불러온 시드의 것인지는 6장 주소 검증으로 이어서 확인 가능.

## 6. 주소 검증

1. 스캔한 주소를 크게 보여 주고 확인(JD). 네트워크가 설정과 다르면 거부(JD·SS).
2. 주소 형식 → 스크립트(P2PKH=44, P2SH=49 P2SH-P2WPKH, P2WPKH=84, P2TR=86). P2WSH는 "멀티시그: M7".
3. 찾는 순서:
   - QR에 번호가 있으면(`bitcoin:<주소>?index=N`) 그 번호부터(SP)
   - 이번 세션에 마지막으로 찾은 번호 주변부터(PP)
   - 불러온 시드 전부, 계정 0 + 이번 세션에 쓴 계정(CC), 수신·거스름 번갈아(SS)
   - 비교는 주소 문자열이 아니라 scriptPubKey로(JD)
4. 진행 화면(시드, 확인한 범위), Esc로 멈춤. 1,000개마다 "더 찾기 / 다른 계정 / 그만"(JD·KX).
5. 찾으면 "확인됨: 시드 73c5da0a · m/84'/0'/0'/0/17 (수신 #17)" + 주소 QR + "이 주소로 메시지 서명"(CC). 못 찾으면 확인한 범위를 그대로 보여 줌(PP·CC).

## 7. 설정 · SettingsQR

- 수수료: 경고 2/5/10%, 차단선 **10%(기본) / 25% / 50%**, 수수료율 경고 500/1,000/5,000 sat/vB. 공격·오류 판정은 설정과 무관.
- 메시지 서명: 기본 꺼짐(결정 3), 설정에서 기기 위에서만 켬.
- 언어: English / 한국어.
- SettingsQR: `bitpunk-settings::v1 키=값 …`(SS 문법). 스캔하면 바뀌는 항목을 보여 주고 확인(기본 취소). **안전을 약하게 하는 항목(메시지 서명 켜기, 차단선·경고선 올리기)은 QR로 적용하지 않고 "기기에서 직접 바꾸세요"로 안내**. 내보내기는 현재 설정 전체.
- M9 전까지 설정은 전원을 끄면 초기화되므로 SettingsQR가 보관 수단.

## 8. D20 주사위

- 시드 만들기 > 주사위 D20. 숫자 입력 후 Space/Enter. 1~20 외 거부.
- Krux와 같게: 값을 `-`로 이은 문자열의 SHA-256, 최소 30회(12단어)·60회(24단어). 기존 검사(치우침·패턴·연속)를 20면으로 확장.

## 9. 한국어 UI

- 글꼴: Noto Sans KR(SIL OFL)에서 한국어 문자열에 쓰인 글자만 SMALL·BODY·TITLE 크기로, 한글은 2비트 계조(KS 방식). HUGE는 숫자·영문만.
- 한글은 영문 2칸. 너비·줄바꿈·정렬을 칸 단위로.
- CI: 한국어 표의 모든 글자가 글꼴에 있어야 통과. 글꼴에 없는 글자는 `□`.
- BIP-39 단어, 주소, 경로, 지문, 비트코인 용어 원어(PSBT, xpub 등)는 그대로.
