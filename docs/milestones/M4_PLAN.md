# M4 구현 계획 — QR 입력

상태: **구현 완료 (2026-11-20)** — 아래 "12. 구현 결과" 참고 · 승인: 권장안(ZXing식 디코더 직접 구현 · 시뮬레이터 웹캠 허용) · 근거: [QR_SURVEY.md](../QR_SURVEY.md) 4장, [QR_SCAN_BENCH.md](../QR_SCAN_BENCH.md)

## 1. 목표

카메라 프레임(흑백 영상)에서 QR을 읽어 **어떤 형식이든 자동으로 알아보고** 알맞은 화면으로 보낸다.
에어갭 기기에서 카메라는 유일한 입력 통로이므로, 출력(M3)과 같은 수준으로 **디코더를 직접 구현**하고 시험대로 성능을 잰다.

## 2. 범위

| 포함 | 나중 |
|---|---|
| QR 디코더 직접 구현 (이진화 → 위치 찾기 → 원근 보정 → 격자 읽기 → 오류 정정 → 데이터 해석) | 카메라 하드웨어 보조(눈부심 방지, 노출) → H 트랙 |
| 반전 QR 재시도, 좌우 반전 QR 재시도 | |
| 애니메이션 수신: UR(fountain 디코딩), BBQr(H/2/Z, **inflate 직접 구현**), Specter `pM/N` + 진행 표시 | |
| 형식 자동 판별 (아래 4장) | 주소 검증 → M6, 서명 요청 → M5·M6 |
| SeedQR·Compact SeedQR·니모닉 텍스트로 **시드 불러오기** | 암호화 시드 QR → M10 |
| SeedQR 옮겨 그린 뒤 **다시 스캔해서 확인** (M3에서 넘어온 항목) | |
| 시뮬레이터 카메라: 이미지 올리기, 웹캠(시뮬레이터 전용), QR 텍스트 붙여넣기 | |

## 3. QR 디코더 설계

| 단계 | 방식 | 참고 |
|---|---|---|
| 이진화 | 8×8 블록별 밝기 통계로 지역 임계값 (조명이 고르지 않아도 됨) | ZXing HybridBinarizer (PP가 사용) |
| 위치 찾기 | 행·열을 훑어 1:1:3:1:1 비율의 위치 패턴을 찾고 교차 검증, 세 개를 모아 방향 결정 | ZXing FinderPatternFinder |
| 원근 보정 | 버전 2 이상은 정렬 패턴을 찾아 4점 호모그래피, 버전 1은 3점 | ZXing Detector |
| 격자 읽기 | 모듈 중심 샘플링 → 비트 행렬 | |
| 형식·버전 | BCH 오류 정정 (형식 정보 2벌, 버전 정보 2벌 비교) | ISO 18004 |
| 오류 정정 | Reed–Solomon 디코딩 (Berlekamp–Massey + Chien 탐색 + Forney) | |
| 데이터 | 숫자·영숫자·바이트 모드, ECI (UTF-8), 길이 검증 | |
| 재시도 | 실패 시 흑백 반전, 좌우 반전 순으로 다시 시도 | PP |
| 메모리 | 할당 없음. 최대 640×480 흑백 프레임 고정 버퍼 (비트 행렬 38KB) | 마이크로컨트롤러 기준 |

**왜 ZXing식인가:** M3 시험대에서 먼 거리(0.35~0.45)는 rxing(ZXing 계열)이 rqrr(quirc 계열)보다 잘 읽었고, 가까운 거리는 둘이 비슷했다. 레퍼런스 중 Passport Prime이 rxing을 쓴다. 코드는 우리가 새로 쓰고, rxing·rqrr는 테스트 비교용으로만 쓴다.

## 4. 형식 자동 판별과 동작

| 읽은 내용 | 판별 | M4에서 하는 일 |
|---|---|---|
| SeedQR (숫자 48/96자리), Compact SeedQR (16/32바이트) | 길이 + 체크섬 | 시드 불러오기: 지문 확인 화면 → 슬롯에 저장 |
| 니모닉 텍스트 (12/24단어, 4글자 줄임말 포함) | 단어장 + 체크섬 | 위와 같음 |
| PSBT: UR `crypto-psbt`/`psbt`, BBQr `P`, base64, hex | 헤더 `psbt\xff` | 수신 완료 화면(크기·입출력 수) — 서명은 M5 |
| xpub·zpub 등 (`[지문/경로]` 포함 가능) | Base58Check + 버전 바이트 | 키 정보 표시 |
| 주소, `bitcoin:` URI (BIP-21) | Bech32/Base58 검증 | 주소 정보 표시 — 내 지갑 소속 검증은 M6 |
| 디스크립터·지갑 설정 | 텍스트 패턴 | 인식만 하고 "M7에서 지원" 안내 |
| 그 외 | — | 원문 보기 (안전하게 잘라서 표시) |

UR은 옛 이름(`crypto-*`)과 새 이름(`psbt`, `output-descriptor` 등)을 모두 받는다.

## 5. 화면

- **스캔 화면**: 카메라 미리보기(흑백), 찾은 QR 위치 표시, 형식 이름, 애니메이션 진행(UR은 받은 비율, BBQr·Specter는 조각 번호 격자). Esc 취소.
- **진입**: 메인 메뉴 "Scan QR", 어디서나 Fn+Q(CardKB QR 키), 시드 불러오기 메뉴의 "SeedQR 스캔".
- **SeedQR 확인**: 옮겨 그리기 가이드에서 "다시 스캔" → 같은 시드면 통과, 다르면 어긋난 단어 위치 안내.

## 6. 시뮬레이터 카메라

| 방법 | 용도 |
|---|---|
| 이미지 올리기 (PNG/JPG) | SeedSigner 등으로 만든 QR 사진 |
| 웹캠 (**시뮬레이터 전용**, 기기는 그대로 무선·USB 없음) | 휴대폰/Sparrow 화면의 애니메이션 QR을 실제로 찍어 보기 |
| QR 텍스트 붙여넣기 | UR 조각 목록 등 빠른 시험 |

## 7. 보안 (QR 내용은 신뢰하지 않는 입력)

- 모든 파서는 길이·범위를 검사하고 **패닉 없음**을 무작위 변형 입력 수만 건으로 시험.
- inflate는 출력 크기 상한(압축 폭탄 방지), UR은 조각 수·메시지 길이 상한.
- SeedQR·니모닉 버퍼는 사용 후 지움. 불러오기 전 지문을 보여 주고 확인을 받음.

## 8. 테스트 & 성능 측정

| 대상 | 방법 |
|---|---|
| Reed–Solomon·BCH | 정정 한도까지 무작위 오류 주입 → 복원, 한도 초과 → 반드시 실패 처리 |
| QR 디코더 | 우리 인코더 + qrcodegen이 만든 전 버전·모드·ECC·마스크를 읽기 |
| 실사진 | **ZXing 블랙박스 QR 사진 세트**(실제 촬영, Apache-2.0, 테스트 전용)에서 rqrr·rxing과 성공 수 비교 |
| 시험대 | M3 시험대에 "우리 디코더" 열 추가 |
| UR | `ur` 크레이트가 만든 조각을 일부 버리고 순서 섞어도 복원, BCR 예제 |
| BBQr·inflate | Coinkite 참조 벡터 복원, `miniz_oxide`가 압축한 무작위 데이터(동적 허프만 포함) 복원 |
| SeedQR | SeedSigner 벡터 |
| 퍼징 | 디코더·UR·BBQr·inflate·형식 판별에 무작위/변형 입력 |

## 9. 커밋 단위

1. Reed–Solomon 디코더 + BCH(형식·버전 정보)
2. 이진화 + 위치·정렬 패턴 찾기 + 원근 보정 → 이미지에서 QR 읽기
3. 디코더 시험: 실사진 세트 + 시험대 열 추가
4. inflate + BBQr 디코더 + Specter 디코더
5. UR 디코더 (bytewords, fountain)
6. 형식 자동 판별 + 각 형식 파서
7. 스캔 화면 + 시드 불러오기 + SeedQR 다시 스캔 확인 + PSBT 수신 화면
8. 시뮬레이터 카메라 (이미지·웹캠·텍스트)
9. 퍼징·문서·배포

## 12. 구현 결과

| 항목 | 결과 |
|---|---|
| Reed–Solomon | 정정 한도 안의 무작위 오류 3,000건 모두 복원, 한도를 넘긴 4,000건 모두 거부. 정정 결과는 항상 다시 검사해 유효한 부호어만 내보냄. 작은 심볼은 ISO 규격의 오해독 방지 부호어만큼 정정 한도를 줄임 |
| QR 행렬 디코더 | 버전 1~40 × ECC 4단계 × 숫자·영숫자·바이트, qrcodegen이 만든 8가지 마스크, ECI·혼합 세그먼트, Kanji(Shift JIS 출력), 좌우 반전, 형식·버전 정보 손상, 무작위 행렬 3,000개 패닉 없음 |
| 영상 스캐너 | ZXing식 파이프라인 + 버전 정보 블록·타이밍 패턴으로 크기 확정 + 패턴 적합도로 원근 보정(quirc의 방식을 참고). 흑백 반전·좌우 반전·모든 방향 |
| 비교 (같은 영상) | 강한 원근 48장: **우리 42** / rqrr 41 / rxing 29 · 흐림·잡음 96장: **우리 68** / rxing 65 / rqrr 51 |
| 실사진 | ZXing 실사진 179장 × 2방향: **우리 325 (90.8%)** / rxing 310 / rqrr 243 ([QR_SCAN_BENCH.md](../QR_SCAN_BENCH.md)) |
| 스캔 시험대 | 기본 화면, 기준 거리: medium **98.2%**, hard **56.1%** (휴대폰 디코더 2종 합쳐 37.9%). CI가 95% 이상을 확인 |
| 속도 (데스크톱) | 640×480 QR 프레임 약 1.5 ms, 잡음 프레임 약 6 ms (가짜 위치 패턴은 형식 정보 게이트에서 바로 버림) |
| UR | `ur` 크레이트가 만든 조각: 순서대로면 순수 조각 수만큼으로 완성, 프레임을 버려도 fountain 조각으로 복원, fountain 조각만으로도 복원, 다른 메시지 조각 거부 |
| BBQr · Specter · inflate | Coinkite 참조 조각과 우리 Z 조각을 순서 없이 합침, inflate는 miniz_oxide의 모든 압축 단계와 일치, 압축 폭탄은 버퍼에서 멈춤 |
| 형식 자동 판별 | SeedQR·Compact SeedQR, 니모닉(전체·4글자), PSBT(바이너리·Base64·hex·UR·BBQr·Specter), xpub(원점 포함), 주소·`bitcoin:` URI, 디스크립터, 텍스트, `crypto-seed` |
| 화면 | 스캔 화면(카메라 미리보기·찾은 윤곽·조각 격자), 시드 지문 확인 후 불러오기, 옮겨 그린 SeedQR 대조(다른 단어 위치 표시), PSBT 수신(버전·입출력 수·크기·전송 방식), 키·주소·디스크립터·텍스트 결과 |
| 시뮬레이터 | 웹캠(스캔 화면에서만 켜지고 저절로 꺼짐) · 이미지 · 텍스트 붙여넣기. Playwright로 SeedQR 사진, 붙여넣은 URI, 가짜 웹캠 영상, 우리 xpub UR 2프레임 왕복을 확인 |
| 퍼징 | 분류기 4만 회, PSBT·Base64·CBOR·UR 분류 2만 회, 변형된 애니메이션 300회, 무작위 영상 40장: 패닉 0건 |

### 계획과 달라진 점

| 계획 | 실제 | 이유 |
|---|---|---|
| ZXing식 위치 찾기·원근 보정 | 여기에 **버전 정보·타이밍 패턴으로 크기 확정**과 **패턴 적합도로 모서리 보정**(quirc 방식)을 더함 | 큰 버전에서 모듈 크기 추정이 5% 틀리면 크기를 잘못 잡았고, 강한 원근에서 정렬 패턴 위치가 크게 빗나감 |
| 바이트·영숫자·숫자 모드 | Kanji 모드도 해석 (Shift JIS 바이트) | 실사진 비교에서 일본어 사진을 공정하게 세기 위해. 비트코인 데이터에는 쓰이지 않음 |
| — | 수집기 저장 공간 32 KB (PSBT 약 32 KB까지) | 기기 메모리 기준. 큰 PSBT가 필요하면 M5에서 조정 |
| 시뮬레이터 웹캠 | claude.ai 아티팩트 안에서는 브라우저가 카메라를 막을 수 있어, 그때는 안내 후 이미지·붙여넣기 사용. GitHub Pages에서는 웹캠 사용 가능 | 아티팩트 런타임이 카메라 권한을 제공하지 않음 |
| — | 앱 상태가 약 200 KB(스캐너·버퍼)라 테스트 스레드 스택을 늘림 (`.cargo/config.toml`) | 디버그 빌드가 큰 구조체를 스택에 복사함. 기기에서는 정적 메모리에 둠 |
