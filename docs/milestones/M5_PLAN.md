# M5 구현 계획 — PSBT 서명 (MVP)

상태: **승인 대기** · 근거: [FEATURE_SURVEY.md](../FEATURE_SURVEY.md) G장, [ROADMAP.md](../ROADMAP.md) M5

## 1. 목표

지갑 앱(Sparrow 등)이 만든 PSBT를 QR로 받아, **사람이 확인할 수 있는 형태로 거래를 보여 주고**, 모든 화면을 확인한 뒤에만 서명해 QR로 돌려준다.

**완료 기준:** Signet에서 Sparrow → Bitpunk(시뮬레이터) → Sparrow 실제 송금 성공.

## 2. 범위

| 포함 | 나중 |
|---|---|
| PSBT v0 전체 파서·직렬화 (BIP-174, 탭루트 필드 BIP-371) | PSBT v2 → M7 |
| 단일 서명 4종: P2WPKH (BIP-84), P2TR 키 경로 (BIP-86), P2SH-P2WPKH (BIP-49), P2PKH (BIP-44) | 멀티시그, 탭루트 스크립트 경로 → M7 |
| 서명 해시 3종: 레거시, BIP-143, BIP-341 | 메시지 서명 → M6 |
| ECDSA (RFC 6979, low-S), Schnorr (BIP-340), **서명 직후 자체 검증** | |
| 거래 검토 화면 + 세분화된 경고 체계 | 경고 강도 설정 → M6 |
| 서명된 PSBT를 QR로 출력 | SD 저장·최종화된 tx 저장 → M8 |

## 3. 암호 (`bp-crypto`)

| 항목 | 내용 |
|---|---|
| 스칼라 | mod n 곱셈·역원 (상수 시간) 추가. 기존: 덧셈·부호 반전 |
| ECDSA | RFC 6979 결정적 nonce (HMAC-SHA256), low-S 정규화, DER 인코딩 |
| Schnorr | BIP-340 (태그 해시, x-only 공개키, 짝수 y 처리), 탭루트 키 트윅 (BIP-341) |
| 서명 후 검증 | 만든 서명을 바로 검증해서, 하드웨어 오류나 버그로 생긴 잘못된 서명이 나가지 않게 함 (Jade·Coldcard 방식) |
| 검증 함수 | 공개 데이터만 다루므로 변동 시간 허용 |
| 상수 시간 | 비밀 키·nonce 연산은 M2처럼 타이밍 측정 |

## 4. PSBT (`bp-bitcoin`)

| 항목 | 내용 |
|---|---|
| 거래 | segwit / 비segwit 직렬화, txid 계산 |
| 서명 해시 | 레거시 (SIGHASH_ALL 등), BIP-143 (segwit v0), BIP-341 (탭루트: 모든 입력의 금액·스크립트를 커밋) |
| 파서 | 전역: unsigned tx, xpub. 입력: non_witness_utxo, witness_utxo, partial_sig, sighash_type, redeem/witness script, bip32 파생, 최종 스크립트, tap_key_sig, tap_internal_key, tap_bip32 파생, tap_merkle_root. 출력: redeem/witness script, bip32 파생, tap_internal_key, tap_bip32 파생 |
| 규칙 | 모르는 키는 그대로 보존. 중복 키·길이 오류·입출력 수 불일치는 BIP-174 규칙대로 거부 |
| 메모리 | 할당 없이 원본 바이트의 위치로 색인. PSBT 최대 32 KB (M4 수집기와 같음) |

## 5. 거래 분석과 경고

**분석**

| 항목 | 방법 |
|---|---|
| 입력 금액 | witness_utxo 또는 non_witness_utxo. segwit v0 입력도 이전 거래 전체가 있으면 txid를 대조 (2020년 수수료 공격 대비) |
| 내 입력 | 파생 정보의 지문이 로드된 시드와 같고, **그 경로로 직접 파생한 키가 UTXO의 스크립트를 재현할 때만** 내 입력으로 인정 |
| 거스름 | 출력의 파생 정보로 만든 스크립트가 출력 스크립트와 **정확히 일치할 때만** 거스름. 아니면 외부 송금으로 표시 |
| 수수료 | 입력 합 − 출력 합, 서명 후 크기(vbyte)를 추정해 sat/vB 표시 |

**오류 (서명 불가)**: 내 입력 없음 · UTXO 정보 누락 · 이전 거래 txid 불일치 · 음수 수수료 (출력 > 입력) · 중복 입력 · 네트워크 불일치 · 파싱 오류

**경고 (한 번 더 확인)**: 수수료 과다 · 거스름 소유권 모순 (파생 정보가 스크립트와 다름) · 다른 계정·스크립트 종류로 가는 거스름 · 일부 입력이 다른 지갑 것 · 비표준 SIGHASH (NONE·SINGLE·ANYONECANPAY) · OP_RETURN 출력 (내용 표시) · 비정상적으로 큰 거스름 주소 번호 · segwit v0 입력에 이전 거래 전체가 없음 (금액 검증 불가) · 서명할 수 없는 입력 (멀티시그 등)

**정보**: locktime, RBF 여부

## 6. 화면

1. **PSBT 수신**: 지문으로 맞는 시드를 자동 선택. 없으면 "로드된 시드 중 일치하는 것이 없음 (패스프레이즈 확인)"
2. **개요**: SeedSigner식 금액 흐름. 입력 합계 → 받는 사람 n명 / 거스름 / 수수료
3. **받는 사람**: 한 명씩 주소(4글자 묶음)와 금액
4. **거스름**: 주소와 경로, "이 시드의 주소로 확인됨" 표시
5. **수수료**: 금액, sat/vB, 보내는 금액 대비 비율
6. **경고**: 있으면 하나씩 확인
7. **서명 확인** → 서명 → 서명된 PSBT QR (M3 표시 엔진, 낮은 밀도·느린 속도로 시작)

모든 화면을 거쳐야 서명할 수 있다. 금액 단위는 설정의 BTC / sats를 따른다.

## 7. 테스트

| 대상 | 방법 |
|---|---|
| Schnorr | BIP-340 공식 벡터 (서명·검증), libsecp256k1과 같은 aux에서 바이트 일치 |
| ECDSA | RFC 6979 secp256k1 벡터, libsecp256k1과 **바이트 일치** (무작위 키·메시지 수천 건), Wycheproof ECDSA secp256k1 (검증), 타이밍 측정 |
| 서명 해시 | BIP-143 예제, BIP-341 지갑 테스트 벡터 (키 경로 서명 해시·서명), Bitcoin Core `sighash.json` (레거시) |
| PSBT | BIP-174·BIP-371 유효/무효 벡터. rust-bitcoin(테스트 전용)으로 4종 지갑의 PSBT를 만들고, 우리 서명을 rust-bitcoin의 독립 서명 해시 계산으로 검증 |
| 경고 | 경고마다 그 상황의 PSBT를 만들어 화면 흐름 확인 |
| 퍼징 | PSBT·거래 파서, 분석기 |
| 실제 | Signet에서 Sparrow 송금 |

## 8. 커밋 단위

1. 스칼라 곱셈·역원 + ECDSA (RFC 6979, low-S, DER) + 검증
2. Schnorr (BIP-340) + 탭루트 트윅 + 서명 후 검증 + 타이밍 측정
3. 거래 파서·직렬화 + 서명 해시 3종
4. PSBT 파서·직렬화 (BIP-174 / 371)
5. 거래 분석 (소유권·거스름·수수료) + 경고 체계
6. 서명 (4종 스크립트) + 서명된 PSBT 출력
7. 검토·서명 화면
8. 서명 결과 QR 출력 + 시뮬레이터 확인
9. 퍼징·문서·배포

## 9. 완료 기준

- [ ] Signet: Sparrow에서 만든 송금 PSBT를 시뮬레이터로 읽고, 검토·서명한 QR을 Sparrow가 읽어 방송까지 성공
- [ ] 4종 스크립트 서명이 rust-bitcoin 독립 검증을 통과하고, ECDSA는 libsecp256k1과 바이트 일치
- [ ] 경고 상황의 PSBT마다 해당 경고가 나오고, 오류 상황에서는 서명할 수 없음
- [ ] 퍼징 패닉 0건, CI 전부 통과

## 10. 결정 필요

1. **서명된 PSBT 출력**: 서명만 남긴 축소본 (권장) / 전체 PSBT
2. **Schnorr 보조 난수 (aux_rand)**: 결정적 = 0 (권장) / 하드웨어 TRNG 섞기 (H 트랙 이후)
3. **수수료 과다 경고 기준**: 보내는 금액의 10% 이상 또는 1,000 sat/vB 초과, 수수료가 보내는 금액보다 크면 강한 경고 (권장) / 다른 기준
4. **출력 형식**: UR 기본 + BBQr·Specter 선택 (권장) / UR만
