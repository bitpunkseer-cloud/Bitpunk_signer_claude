# M10 구현 계획 (v1) — 보안 저장 · PIN · 시드 보관함

상태: **구현 완료 (2026-11-25)** — 승인 (결정 1~12 권장안), 단위 M10-0~M10-9 완료, 실기기 연결은 H 트랙 ([SE050 드라이버](../M10_SE050.md) 5절) · 이전 상태: 진행 중: M10-0~M10-8 완료 ([SE050 드라이버](../M10_SE050.md)) · 근거: [M10_SURVEY.md](../M10_SURVEY.md) (Coldcard·Passport·Keystone·OneKey·Specter·Krux·Jade·SeedSigner 코드, STM32N6 HAL 드라이버) · 화면은 [UX 언어 v1.0](../UX_LANGUAGE.md)을 따른다.

## 1. 목표

지금까지 기기는 **아무것도 저장하지 않는다**(전원을 끄면 시드·설정·지갑이 사라짐). M10은 사용자가 원할 때만 시드·멀티시그 지갑·설정을 **기기에 암호화해 보관**하고, PIN으로 잠그며, 도난·플래시 탈취·롤백·피싱·강요를 견디게 한다.

**완료 기준**
- 보관함을 켜지 않으면 기기는 M9와 **똑같이** 동작한다(기능 대장·M8 골든 출력·과제 키 수 그대로).
- 플래시를 떼어 읽어도, 옛 플래시 내용으로 되돌려도, 다른 기기에 옮겨도 시드를 얻을 수 없다(시험으로 재현).
- 틀린 PIN은 되돌릴 수 없게 세고, 한도를 넘으면 보관함이 **복구 불가능하게 지워진다**(암호 소거).
- 가짜 펌웨어·다른 기기는 사용자가 기억한 **피싱 방지 단어**를 만들 수 없다.
- 강요 상황용 **속임수 PIN**(미끼 지갑·조용히 지우기·빈 기기 흉내).
- 새 암호 요소(Argon2id·ChaCha20-Poly1305·HKDF·BLAKE2b)는 독자 구현이고 표준 시험 벡터와 참조 크레이트(시험에서만)로 교차 검증한다.

## 2. 위협과 대응

| # | 위협 | 대응 |
|---|---|---|
| T1 | 기기 분실·도난(PIN 모름) | 보관함 키 = PIN(Argon2id) + 보안 칩 비밀 + 칩 고유 키. 셋 중 하나라도 없으면 못 연다 |
| T2 | 외부 플래시를 떼어 읽음 | 기기 키를 **SAES DHUK로 감싸** 저장 — 이 칩 밖에서는 풀 수 없음 |
| T3 | 플래시를 옛 내용으로 되돌려 시도 횟수 초기화 | 횟수는 **보안 칩이 셈**(되돌릴 수 없음). 보관함 머리말에 보안 칩 단조 카운터 값을 넣어 옛 내용은 거부 |
| T4 | PIN 맞히기(무차별 대입) | 보안 칩의 시도 한도(10회) + Argon2id(메모리 수 MiB) + 늘어나는 대기 시간 |
| T5 | 가짜 펌웨어·바꿔치기 기기로 PIN 가로채기 | PIN 앞부분 → **단어 2개**(보안 칩 HMAC 키 + 기기 키로 계산). 틀리면 뒷부분을 치지 않는다. 탬퍼 점검 코드로 펌웨어 변경 확인. 서명 부팅은 M12 |
| T6 | 강요("열어라") | 속임수 PIN: 미끼 지갑(BIP-85로 만든 다른 시드), 조용히 지우기, 빈 기기 흉내 |
| T7 | PIN을 잊음 | 보관함은 **편의 기능**. 백업 검사를 통과한 시드만 넣을 수 있고, 켤 때마다 "단어 백업이 유일한 복구 수단" 안내 |

## 3. 설계

### 3-1. 키 구조 (결정 1의 권장안 B 기준)

```
PIN ──Argon2id(salt, m, t, p)──► P (32 B)
                                   │
보안 칩(SE050): 인증 객체(시도 10회) ── P로 인증해야만 ──► S (32 B, 칩 안에서 생성)
MCU: 기기 키 D (32 B) ── SAES DHUK로 감싸 플래시에 ── 이 칩만 풀 수 있음
                                   │
보관함 키 K = HKDF-SHA256(P ‖ S ‖ D, salt, "bitpunk vault v1")
보관함 = ChaCha20-Poly1305(K, 논스, 내용, 추가 데이터 = 머리말 전체)
```

- 세 비밀 중 하나만 새어도 시드는 안전하다(CC의 "세 칩 모두"·PP의 "SE+SECURAM+PIN"과 같은 원칙).
- 10회 틀리면 보안 칩이 인증 객체를 영구히 잠근다 → S를 다시 못 꺼냄 → 보관함은 복구 불가(암호 소거). 펌웨어는 플래시의 보관함도 지우고 새 기기처럼 시작한다.
- **롤백 방지:** 보관함을 쓸 때마다 보안 칩의 단조 카운터를 올리고 그 값을 머리말(추가 데이터)에 넣는다. 읽을 때 카운터와 다르면 거부.
- 보안 칩 없이(권장안 A 선택 시): S가 빠지고 횟수는 플래시에 남는다 → 되돌리기 공격에 약해지므로 PIN을 더 길게(12자 이상) 요구하고 위험을 화면에 적는다.

### 3-2. PIN과 피싱 방지 단어

- 영숫자·기호(QWERTY): **앞부분 4–8자 → Enter → 단어 2개 확인 → 뒷부분 4자 이상**(총 8자 이상).
- 단어 = BIP-39 단어 2개 = `HMAC(보안 칩 안의 키, HMAC(D, 앞부분))`의 비트. 기기마다 다르고, 다른 기기·가짜 펌웨어는 만들 수 없다.
- 단어가 다르면 뒷부분을 치지 말라는 안내(빨간 `[!!!]`). 단어 화면에서는 아무 PIN 정보도 저장·전송하지 않는다.
- 입력 중 글자는 `*`로, 앞부분 단어는 `BRIGHT`.

### 3-3. 잠금 해제·오입력

- 부팅 → 보관함이 있으면 **잠금 화면**(앞부분 → 단어 → 뒷부분 → Argon2id 계산 중 비 띠 → 열림).
- "보관함 없이 사용"을 고르면 지금처럼 상태 없는 세션(보관함은 잠긴 채). 기존 기능은 모두 그대로.
- 틀리면 `[WARN] 남은 시도 n회`. 4번째부터 대기: 1분 → 5분 → 15분 → 1시간(전원이 켜져 있는 동안 셈, 보안 칩 한도와 별개).
- 10회째 틀리면 보관함 암호 소거 → "보관함이 지워졌습니다" → 새 기기 상태.

### 3-4. 속임수 PIN (결정 6)

| 종류 | 동작 |
|---|---|
| 미끼 지갑 | 정상처럼 열리지만 **다른 시드**(설정할 때 진짜 시드에서 BIP-85 번호 1001~1003으로 만들어 그 PIN으로 암호화해 둠) |
| 조용히 지우기 | 보관함을 암호 소거하고 "PIN이 틀렸습니다"처럼 보이거나 미끼 지갑으로 |
| 빈 기기 흉내 | 아무것도 지우지 않고 보관함이 없는 기기처럼 시작 |

- 속임수 PIN은 진짜 PIN보다 **먼저** 검사하고, 맞으면 보안 칩 시도 횟수를 쓰지 않는다(CC 방식). 목록은 기기 키로 암호화해 머리말에 둔다(모두 같은 길이, 상수 시간 비교).
- Delta 모드·벽돌은 넣지 않는다(오조작 위험이 크고, 보관함 소거로 충분).

### 3-5. 보관하는 것 (결정 7)

| 항목 | 저장 | 메모 |
|---|---|---|
| 시드 | 니모닉 엔트로피(16/32 B)·XPRV·WIF, 이름(지문) | 최대 8개. 열면 RAM 슬롯 3개로 불러옴 |
| 멀티시그 지갑 | 등록한 지갑과 지갑 코드 | 다음 세션에 코드 입력 없이 |
| 설정 | 지금 설정 전부 | 언어만 잠금 화면용으로 머리말에 평문 |
| **저장 안 함** | 패스프레이즈, BIP-85 결과, 서명한 거래·금액 기억, 세션 로그 | 지금처럼 RAM에서만 |

- 저장 위치: 외부 플래시의 보관함 구역 두 칸(A/B), 순번·CRC로 쓰는 도중 전원이 꺼져도 한 칸은 늘 온전.

### 3-6. 탬퍼 점검 코드 (결정 12)

- 사용자가 코드를 정해 두면, 부팅 점검 로그에서 요청할 때 `HMAC(D, 코드 ‖ SHA-256(펌웨어 이미지))`로 **단어 2개**를 보인다. 펌웨어가 바뀌면 단어가 바뀐다(KX 방식을 기기 키로 강화).

### 3-7. 하드웨어 추상화와 시뮬레이터

- `bp-hal`에 새 트레이트(새 파일): `SecureElement`(인증·비밀 꺼내기·HMAC·단조 카운터·잠김), `DeviceKey`(감싸기·풀기), `VaultFlash`(구역 읽기·지우기·쓰기).
- 시험·시뮬레이터용 모의 구현은 **실제 칩과 같은 규칙**(시도 한도 후 영구 잠김, 카운터는 올라가기만)을 지킨다.
- 시뮬레이터: 보관함은 **페이지 메모리에만**(시뮬레이터 전원 끄기 → 다시 켜기에는 남고, 페이지 새로고침이면 새 기기). 브라우저 저장소에는 절대 쓰지 않는다. 페이지에 "시뮬레이터: 시험용 시드만" 경고 유지.
- 실기기(H 트랙): OM-SE050ARD-E 실드(I2C 0x48, CardKB와 같은 버스), SAES 드라이버, XSPI 플래시 쓰기, TAMP 설정.

## 4. 화면 (UX 언어 준수)

| 새 화면 | 쓰는 부품 |
|---|---|
| 잠금 화면(앞부분·단어·뒷부분·계산 중·실패·대기·지워짐) | 상태줄 경로 `BITPUNK:~/Locked>`, 입력 칸, 단어 `TITLE`+`BRIGHT`, 로그 줄(`[WARN] 남은 시도`), 계산 중 비 띠, 경고 3단계 |
| PIN 정하기·바꾸기(규칙, 두 번 입력, 단어 외우기) | 확인 화면의 틀, 로그 줄 |
| 시드 보관함(목록·넣기·꺼내기·지우기) | 목록(`list`), 지문 `DOUBLE`, 지우기는 단어 입력 확인 |
| 보안 설정(PIN·속임수 PIN·대기·탬퍼 점검 코드·보관함 지우기) | 설정 목록, 보관함 지우기는 `WIPE` |
| 탬퍼 점검 코드 결과 | 단어 `DOUBLE` |

- 새 화면은 UX 언어 8장 점검표를 모두 지킨다(전수 등록·도움말 주제·테마 색·넘침·기능 대장·점검표·오류 코드).

## 5. 기능 보존

- 보관함이 없으면 부팅·메뉴·흐름이 M9와 같다. 과제 효율 시험(`task_*`)은 그대로 통과해야 한다.
- 새 동작은 의도한 변경 목록에 번호를 붙인다(M10에서 D1~): 잠금 화면, 메뉴에 "시드 보관함"·"보안" 추가, 첫 실행 화면 문구("M10 전까지 저장 없음" → 보관함 안내).
- 동결(결정 11): 서명·검증·파싱(`bp-bitcoin`·`bp-qr`·`bp-fat`)과 기존 암호 파일은 계속 동결. 새 암호 요소와 HAL 트레이트는 **새 파일로만** 추가.

## 7. 커밋 단위

1. **M10-0 기반:** 파일 단위 동결, 기능 대장에 M10 절, 시험 틀
2. **M10-1 암호 요소:** BLAKE2b, Argon2id, ChaCha20-Poly1305, HKDF — 표준 벡터 + 참조 크레이트 교차 검사 + 상수 시간 점검
3. **M10-2 HAL 트레이트·모의 구현:** 보안 칩·기기 키·보관함 플래시, 모의 구현은 실제 규칙대로(시도 한도·단조 카운터)
4. **M10-3 보관함 형식:** 머리말·레코드·A/B 쓰기, 쓰는 도중 모든 지점에서 전원 끊기 시험, 롤백 거부
5. **M10-4 PIN:** 정하기·바꾸기, 피싱 방지 단어, 잠금 화면, 대기, 10회 암호 소거
6. **M10-5 시드 보관함:** 넣기·꺼내기·지우기, 멀티시그 지갑·설정 보관
7. **M10-6 속임수 PIN:** 미끼 지갑·조용히 지우기·빈 기기 흉내
8. **M10-7 탬퍼 점검 코드**
9. **M10-8 SE050 드라이버:** T=1 over I2C, APDU, SCP03 — 기록한 통신 내용과 모의 칩으로 시험(실기기 연결은 H 트랙)
10. **M10-9 공격 시험·퍼징·시뮬레이터·문서·배포**

| 암호 요소 | RFC 7693·9106·8439·5869 벡터, 참조 크레이트와 무작위 입력 수천 건 일치 |
| 보관함 형식 | 손상·잘림·순서 바꿈·다른 기기 키·옛 카운터 → 모두 거부, 퍼징 |
| 전원 끊김 | 쓰기의 모든 단계에서 끊고 다시 켜 → 옛 내용 또는 새 내용 중 하나가 온전 |
| 롤백 | 플래시를 옛 사본으로 되돌림 → 거부, 시도 횟수 그대로 |
| PIN | 10회 → 암호 소거(모의 칩이 영구 잠김), 대기 시간, 속임수 PIN이 시도 횟수를 쓰지 않음, 비교는 상수 시간 |
| 피싱 방지 단어 | 같은 기기·같은 앞부분 → 같은 단어, 다른 기기 → 다른 단어 |
| 기능 보존 | 보관함 없이 M9 시험 전부 + 골든 출력 + 과제 효율 그대로 |
| 화면 | UX 언어 8장 점검표(전수 등록·도움말·색·넘침·대장·점검표) |

### 9-2. 알려진 한계

- **플래시 변조 = 지우기와 같음.** 머리말·속임수 칸·본문은 인증되므로 바뀌면 열리지 않는다. 시드는 단어 백업으로 되살린다.
- **SE050 기본 SCP 키 교체**(PUT KEY)와 "SCP 필수" 설정은 실기기에서 해야 실제로 안전하다(H 트랙, [M10_SE050](../M10_SE050.md) 3절).
- **탬퍼 점검의 범위**: 서명 부팅(M12) 전까지는 기기 키와 보안 칩에 닿는 정교한 악성 펌웨어가 진짜 단어를 계산할 수 있다.
- **미끼 상태에서 바꾼 것**은 전원을 끄면 사라진다. **조용히 지운 뒤** 다시 켜면 보관함이 없는 기기로 보인다.
- **Argon2id 비용**(8 MiB, t=3)은 실기기에서 잠금 해제 약 2초가 되게 조정한다.
