# M1 구현 계획 — 시드 생성 · 입력

상태: **구현 완료 (2026-11-20)** — 아래 "구현 중 변경" 참고

## 0. 확정된 결정

| 결정 | 내용 |
|---|---|
| 시드 생성 방법 | **주사위(D6)와 동전 던지기만** 사용. 기기 난수로 시드를 만드는 기능은 두지 않음 |
| 엔트로피 처리 | 나온 값을 이어 붙인 문자열의 SHA-256 (SeedSigner·Krux·Coldcard 방식) |
| 엔트로피 검사 | 횟수·추정 엔트로피·치우침·반복 패턴·연속 반복을 실시간 표시. **하나라도 실패하면 시드 생성 불가** |
| 백업 확인 | **모든 단어를 객관식 퀴즈**로 확인. **통과하지 못하면 시드 생성 불가** |

### 용어
- **기기 난수**: 칩이나 소프트웨어가 만드는 난수(브라우저의 `crypto.getRandomValues` 포함). 시드 재료로 쓰지 않음.
- **물리 엔트로피**: 사용자가 직접 굴린 주사위·던진 동전. 시드 재료는 이것뿐.
- 기기 난수는 퀴즈 보기 순서 섞기처럼 비밀과 무관한 곳에만 사용.

## 1. 목표

기기에서 BIP-39 시드를 **주사위·동전으로 만들고, 입력하고, 백업을 확인**할 수 있게 한다.

## 2. 범위

| 포함 | 제외 (다른 마일스톤) |
|---|---|
| SHA-256, SHA-512, HMAC-SHA512, PBKDF2-HMAC-SHA512 | 지문(XFP)·xpub·주소 → M2 |
| BIP-39 영문: 엔트로피 ↔ 니모닉, 체크섬, 시드 계산 | 패스프레이즈 입력 화면 → M2 |
| 주사위 D6 / 동전 시드 생성 + 엔트로피 검사 | D20 → M6 |
| QWERTY 단어 입력 + 자동완성, 단어 번호 입력 | SeedQR → M3/M4 |
| 마지막 단어 계산기 (뽑은 11/23단어 + 동전 7/3회, 퀴즈 필수) | 기기 내 저장 → M9 (M1은 무상태) |
| 단어 표시, 전체 단어 객관식 퀴즈, 세션 시드 목록 | 한국어 → M6 (문자열 표 구조는 M1에서 만듦) |

## 3. 시드 생성 규칙

### 3.1 입력과 해시
| | 주사위 D6 | 동전 |
|---|---|---|
| 키 | `1`~`6` | `1`/`H` = 앞면, `0`/`T` = 뒷면 |
| 기록 문자 | `'1'`~`'6'` | `'1'`(앞면) / `'0'`(뒷면) |
| 1회당 최대 엔트로피 | log2(6) ≈ 2.585비트 | 1비트 |
| 최소 횟수 12단어 / 24단어 | **50 / 100** | **128 / 256** |
| 엔트로피 | `SHA-256(기록 문자열)` → 12단어는 앞 16바이트, 24단어는 32바이트 |

- 최소 횟수 = `ceil(목표 비트 / 1회당 최대 비트)`. 24단어 주사위는 99회로는 255.9비트라 256비트에 못 미쳐 **100회**로 정함.
- 최소 횟수를 넘겨 더 굴려도 되고, 추가 값도 모두 해시에 들어감(Krux 방식).
- 확인 화면에 기록 문자열의 SHA-256을 보여 줘서 외부 도구(예: `echo -n 1625… | sha256sum`)로 검증 가능.

### 3.2 엔트로피 검사 (모두 통과해야 생성 가능)

| 검사 | 기준 | 근거 |
|---|---|---|
| 횟수 | 최소 횟수 이상 | 위 표 |
| 추정 엔트로피 | `N × H(관측 빈도)` ≥ 128 / 256비트 | Krux. 관측 빈도 기반 샤논 엔트로피로, 실제보다 낮게 나오는 보수적인 추정치 |
| 치우침 | 카이제곱 적합도 검정, 유의수준 0.1% (주사위 χ² ≤ 20.52, 동전 χ² ≤ 10.83) | Coldcard의 비율 기준을 통계 검정으로 강화 |
| 반복 패턴 | 자기상관(시차 1~16, 시차당 40쌍 이상) \|z\| ≤ 4 + 주사위는 연속 차이값 엔트로피 부족분 ≤ 30% (Krux) | `123456…`, `162534…`(섞은 묶음 반복), `0101…` 차단 |
| 연속 반복 | 같은 값 연속: 주사위 8회 미만, 동전 20회 미만 | 공정한 경우 0.1% 수준에서만 발생 |

- 공정한 주사위로 최소 횟수만 굴리면 추정 엔트로피가 목표에 조금 못 미치는 경우가 많습니다. 이때는 엔트로피 막대가 목표에 닿을 때까지 몇 번 더 굴리면 됩니다(대개 2~5회).
- SeedSigner의 공식 벡터(`5222…555`)는 2와 5만 나오는 극단적 입력이라 **화면에서는 치우침 검사에 걸려 거부됩니다**. 해시 호환성은 단위 테스트로 직접 검증합니다.

### 3.3 백업 퀴즈
- 모든 단어를 **무작위 순서**로 물음: "7번째 단어는?" + 보기 4개(정답 1 + 다른 단어 3).
- 보기 선택: `1`~`4` 키 또는 ▲▼ + Enter.
- **한 번이라도 틀리면 퀴즈 실패 → 시드를 만들지 않음.** 선택지: ① 단어를 다시 보고 퀴즈 재도전 ② 시드 폐기.
- 모든 문제를 맞혀야 시드가 세션에 불러와짐.

## 4. 구현 내용

- `bp-crypto`: SHA-256/512(스트리밍), HMAC-SHA512, PBKDF2-HMAC-SHA512, 퀴즈용 SHA-256 기반 결정적 난수기(DRBG). `no_std`, 할당 없음.
- `bp-bitcoin::bip39`: 공식 단어장(SHA-256 고정), `Mnemonic`(drop 시 지움), 체크섬, 시드 계산, 접두어 검색, 마지막 단어 계산.
- `bp-bitcoin::entropy`: 주사위·동전 기록, 검사 5종, SHA-256 → 니모닉. 로그 계산은 `core`만으로 직접 구현.
- `bp-ui`: 단어 입력, 단어 격자, 빈도 막대, 엔트로피 막대, 검사 목록, 객관식 보기 위젯. 시뮬레이터에 TEST ONLY 배지.
- `bp-app`: 문자열 표, 화면 흐름, 세션 시드 목록(최대 3개).

## 6. 테스트

| 대상 | 방법 |
|---|---|
| SHA-256/512 | NIST 예제 벡터 + 테스트 전용 `sha2`와 무작위 입력 대조 |
| HMAC / PBKDF2 | RFC 4231 + 테스트 전용 `hmac`·`pbkdf2` 대조 |
| 단어장 | 공식 `english.txt` SHA-256 = `2f5eed53…3b24dbda`, 테스트 전용 `bip39` 크레이트 단어장과 2048개 일치 |
| BIP-39 | Trezor 공식 벡터 + `bip39` 크레이트 대조 |
| 주사위·동전 해시 | SeedSigner 공식 벡터 2건 + 직접 계산 대조 |
| 엔트로피 검사 | 공정 입력 다수(통과), `111…`·`123456…`·`0101…`·`2와 5만` 같은 입력(거부) |
| 퀴즈 | 정답·오답 흐름, 실패 시 시드가 생성되지 않는지 |
| 마지막 단어 | 화면 결과를 `bip39::final_word`·Python `hashlib`과 대조 |
| 비밀값 | `Debug` 비노출, drop 시 0으로 지움 |

## 7. 완료 기준 (시뮬레이터에서 확인)

- [ ] 주사위: 최소 횟수 전에는 Enter가 막히고, 검사 결과가 실시간으로 바뀜
- [ ] `123456123456…`처럼 규칙적으로 넣으면 "반복 패턴" 실패로 생성 불가
- [ ] 동전: `0101…` 교대로 넣으면 런 검정 실패로 생성 불가
- [ ] 정상 입력 → SHA-256 표시 → 단어 표시 → 퀴즈에서 하나 틀리면 생성 불가, 모두 맞히면 생성
- [ ] 단어 타이핑: 4글자 자동 확정, 틀린 체크섬 감지 후 해당 단어 수정
- [ ] 상태바에 TEST ONLY 배지 상시 표시
- [ ] CI 전부 통과

## 8. 구현 중 변경

| 변경 | 이유 |
|---|---|
| 반복 패턴 검사에 **자기상관 검정** 추가 | Krux의 차이값 검사만으로는 `162534162534…`처럼 섞은 묶음을 반복한 입력이 통과함 (빈도 완벽, 차이값 6종 → 부족분 25%로 기준 30% 미만) |
| 통계 검사(치우침·패턴)는 **최소 횟수 도달 후** 평가 | 표본이 작을 때 평가하면 공정한 입력도 4% 가까이 오탐. 변경 후 정직한 사용자 시뮬레이션(각 3,000~5,000회): 오탐 0.1~0.4%, 최소 횟수보다 평균 1회 더 굴리면 통과 (99%가 4~5회 이내) |
| 단어 자동완성: 유일 + (4글자 이상 또는 단어 전체) 일 때 확정, 이후 이어 치는 글자는 무시 | `aba`에서 확정되면 네 번째 글자가 다음 단어로 넘어가는 문제. 이제 `aban`·`abandon` 모두 동작 |
| 마지막 단어 계산기: 보류 후 **사용자 결정으로 구현** | 단어는 무작위로 뽑아야 한다는 안내를 먼저 보여 주고, 남은 비트는 동전으로만 채움. 단어 선택은 기기가 측정할 수 없으므로 엔트로피 검사 대신 안내로 대체. 전체 단어 퀴즈는 동일하게 필수 |
| 오탐 시 대처 | 정직하게 굴렸는데 실패가 뜨면: 몇 번 더 굴리거나(Back으로 되돌리기 가능) 처음부터 다시 |
| 화면 문구 | `view.rs`에 남아 있던 영어 문구까지 모두 `text.rs`로 이동. 숫자가 들어가는 문장은 `{}` 템플릿으로 저장해 번역 시 어순 변경 가능 |
