# M8 구현 계획 (v1) — microSD · BIP-85 · 개인키 가져오기

상태: **구현 완료 (2026-11)** — 결정 1~9 전부 권장안으로 승인, 결과는 14장, Sparrow SD 왕복 안내는 15장 · 근거: [M8_SURVEY.md](../M8_SURVEY.md) (Coldcard·Krux·Specter DIY·Passport·Keystone·OneKey·Jade 조사, BIP-85 2.1.0)

## 0. 원칙 — SD 카드는 신뢰할 수 없는 매체

| 원칙 | 내용 | 가져온 곳 |
|---|---|---|
| **SD는 공격자가 만든 것으로 본다** | 파일시스템 구조(BPB·FAT·디렉터리)와 파일 내용을 모두 엄격히 검사. 고리·교차 체인, 거짓 크기, 깨진 긴 이름은 거부하고 패닉·무한 반복 없음(퍼징) | 일반 원칙 |
| **비밀은 SD에 쓰지 않는다** | 시드 단어, BIP-85 결과, WIF·XPRV는 화면과 QR로만 (결정 6) | CC·SP·KX의 약점 보완 |
| **읽고 바로 뗀다** | 작업마다 마운트 → 내용을 내부 버퍼로 복사 → 즉시 언마운트(실기기는 전원 차단). 처리 중에는 카드와 무관 | CC, SP |
| **덮어쓰지 않는다** | 같은 이름이 있으면 번호를 붙인다. 지우기는 사용자가 고른 파일만, 확인 후 | CC |
| **SD로 보호를 약하게 할 수 없다** | 설정 파일은 SettingsQR과 같은 "약화 금지", 지갑 파일은 시드 태그가 맞을 때만 자동 등록 | M6, M7 원칙 |
| **독립 구현** | FAT 코드도 직접 작성(결정 1). 기존 크레이트(rust-fatfs)는 시험의 바깥 기준으로만 | 프로젝트 원칙 |

## 1. 목표

**완료 기준**
- Sparrow가 SD에 저장한 PSBT를 Bitpunk가 읽어 검토·서명하고, 서명한 PSBT를 SD에 저장 → Sparrow가 읽어 방송 (Signet, 단일 서명·2-of-3 모두)
- M7 지갑을 SD 지갑 파일로 저장하고, 다음 세션에 코드 입력 없이(시드 태그 확인) 다시 등록
- BIP-85 결과가 본문 시험 벡터와 모두 일치
- WIF·XPRV를 가져와 그 키의 입력에 서명 (rust-bitcoin으로 독립 검증)
- 시뮬레이터의 가상 SD 카드로 위 흐름을 모두 해 볼 수 있음
- 망가뜨린 파일시스템 이미지 퍼징에서 패닉·무한 반복 없음

## 2. 범위

**포함:** FAT32·FAT16 읽기/쓰기(긴 이름 포함), 기기에서 SD 포맷, 파일 관리자, PSBT 파일 서명, 메시지 파일 서명, 지갑·키·설정 파일 주고받기, SD 제거 알림, BIP-85, WIF·XPRV 가져오기와 단일 키 서명, 가상 SD(시뮬레이터), 보드 후보 비교 문서(H1).

**제외:**

| 항목 | 이유 | 시기 |
|---|---|---|
| exFAT | 구조가 복잡해 공격 표면이 큼 → 기기에서 FAT32로 포맷 (결정 2) | 필요 시 |
| 암호화 백업(시드를 SD에) | 저장 암호화 설계(KDF·AEAD)는 칩이 정해진 뒤 | M10·M11 (로드맵 v3 번호) |
| 펌웨어 설치·업데이트 | 서명된 펌웨어 검증 체계와 함께 | M12 (로드맵 v3 번호) |
| 서명 후 최종 거래 만들기(finalize) | 지금처럼 코디네이터 몫 (M5 결정 유지) | — |

## 3. FAT 구현 (`bp-fat` 크레이트, `no_std`·할당 없음)

- **블록 장치 추상:** `read(lba, &mut [u8; 512])`, `write(lba, &[u8; 512])`. 실기기 드라이버(SDMMC/SPI)는 보드가 정해지면 H 트랙에서.
- **읽기:** MBR 파티션 표(첫 FAT 파티션) 또는 파티션 없는 카드, BPB 검사(섹터 512, 클러스터 크기 2의 거듭제곱, FAT 크기·개수, 클러스터 수로 FAT16/32 판정), FAT 두 벌 중 첫 벌 사용.
- **체인 안전:** 체인 길이는 전체 클러스터 수를 넘지 못함(고리 차단), 범위 밖 클러스터 거부, 파일 크기 ≤ 체인 길이 × 클러스터 크기.
- **디렉터리:** 루트 + 하위 폴더(깊이 4까지), 한 폴더 항목 상한, 긴 이름 조각의 순서·체크섬 검사(어긋나면 8.3 이름으로), 표시 이름은 인쇄 가능한 문자만(나머지는 `?`), 숨김·시스템·`._`(macOS) 파일은 기본으로 숨김.
- **쓰기:** 새 파일만(덮어쓰기 없음): 빈 클러스터 확보 → 데이터 → FAT 두 벌 → 마지막에 디렉터리 항목(중간에 카드를 빼도 기존 파일은 안전, 새 파일만 없음). 긴 이름 항목 작성, 지우기(항목 표시 + 체인 해제), FSInfo는 힌트로만 쓰고 믿지 않음.
- **포맷:** 앞부분을 난수로 덮은 뒤 FAT32(작은 카드는 FAT16) 생성. 확인 2단계.
- **시험:** rust-fatfs(개발 의존성)로 만든 이미지를 우리가 읽고, 우리가 쓴 이미지를 rust-fatfs가 읽어 내용 일치. 이미지 퍼징(BPB·FAT·디렉터리 무작위 손상).

## 4. SD 수명 주기와 화면

- 카드 감지(실기기: 감지 핀 디바운스), 상태 표시줄에 SD 아이콘.
- 작업마다 마운트 → 끝나면 언마운트. 쓰는 중 카드를 빼면 "쓰기 실패 — 카드를 다시 넣으세요"(재시도/취소), 읽은 내용은 이미 내부 버퍼에 있어 처리에 영향 없음.
- 작업이 끝나면 "카드를 빼도 됩니다" 안내(사생활: PSBT가 카드에 남음).
- **파일 관리자** (주 메뉴 > SD 카드): 폴더 탐색, 파일 정보(크기, 내용으로 판별한 종류), 텍스트 보기, 열기(종류별: PSBT → 검토, 지갑 → 가져오기, 메시지 → 서명, 설정 → 가져오기), 지우기(확인), SD 포맷.

## 5. PSBT 파일

- **목록:** `.psbt`·`.txt`·`.base64` 등에서 내용으로 PSBT 판별(바이너리·hex·base64), 이름에 `-signed`가 든 파일은 서명 목록에서 제외(파일 관리자에서는 보임).
- **크기:** 최대 128 KB(디코딩하며 검사), 넘으면 거부. 지금 QR 버퍼(32 KB)보다 큰 거래(많은 입력의 통합)를 위해 SD 전용 버퍼를 둠(실기기는 보드 RAM에 따라 조정).
- **검토·서명:** QR과 같은 화면·규칙(M5·M7 검증기 그대로).
- **저장:** 원래 PSBT에 **우리 서명을 더한 전체 PSBT**(결정 3: SD는 크기 제약이 없어 다음 서명자가 그대로 이어 서명 가능). 이름은 `원래이름-signed.psbt`, 멀티시그는 `원래이름-signed-<지문>.psbt`(서명자끼리 겹치지 않음), 있으면 `-2`, `-3`…(결정 4). 저장 후 파일 이름 표시.
- **원본 지우기:** 기본 꺼짐. 설정에서 켜면 0으로 덮고 → 이름을 바꾼 뒤 → 삭제, "플래시 메모리는 지운 내용이 남을 수 있음" 안내 (결정 5).
- **메시지 파일:** `.txt` 1~3줄(`signmessage` 형식 또는 메시지·경로) → M6 서명 화면 → armored `.sig` 저장.

## 6. 지갑·키·설정 파일

| 파일 | 내용 | 읽을 때 |
|---|---|---|
| 지갑 등록 파일 `이름.bpw` | 이름, 지갑 코드, **256비트 태그**(M7 `CodeKey::tag`), 디스크립터 | 불러온 시드 중 하나로 태그가 맞으면 **코드 입력 없이 등록**(등록 규칙은 다시 검사). 안 맞으면 일반 가져오기(공동서명자 확인 또는 코드) |
| 디스크립터·Coldcard 파일 | M7 내보내기와 같은 내용 | M7 가져오기와 같음 |
| 멀티시그 키 `ccxp-<지문>.json` | Coldcard xpub JSON | Sparrow·Nunchuk가 읽음 |
| 단일 서명 xpub `bitpunk-<지문>.json` | Coldcard "Generic JSON"과 같은 모양(BIP-44/49/84/86 xpub) | Sparrow·Specter·Nunchuk |
| 설정 `bitpunk-settings.txt` | SettingsQR과 같은 문장 | **약화 금지** 규칙 그대로(메시지 서명 켜기·차단선 올리기는 기기에서만) |

태그는 시드 없이는 만들 수 없으므로 파일을 바꿔치기하면 자동 등록이 되지 않는다. 오래된(예전에 등록했던) 지갑 파일을 다시 넣는 것은 막지 않는다 — 사용자가 등록했던 지갑이므로.

## 7. BIP-85 (도구 > BIP-85 자식 키)

- 앱: **BIP-39 니모닉 12/18/24, WIF, XPRV, HEX(16~64바이트), 패스워드 BASE64(20~86자), BASE85(10~80자)** (결정 8: DICE는 SHAKE256 구현이 필요해 선택).
- 번호 입력(0~2³¹−1), 결과 화면에 경로·지문, 비밀이므로 시드 단어와 같은 경고·화면 정리.
- 출력: 화면, QR(니모닉은 Compact SeedQR도), **유도된 시드를 빈 슬롯에 불러오기**. SD 저장 없음(결정 6).
- 패스프레이즈가 걸린 시드면 "패스프레이즈가 결과에 반영됩니다" 안내.
- XPRV는 본문 경고대로 체인코드(앞)·개인키(뒤) 순서.
- 시험: 본문 벡터 전부(니모닉 3종, WIF, XPRV, HEX, PWD 2종), 외부 기준으로 embit의 BIP-85 결과 고정 벡터.

## 8. WIF · XPRV 가져오기 (시드 > 불러오기)

- **입력:** QR, 키보드 (결정 7: SD 텍스트 파일에서 개인키 읽기는 하지 않음 — 평문 키를 카드에 두는 습관을 만들지 않기 위해).
- **XPRV:** `xprv`/`tprv`(SLIP-132 `yprv`/`zprv` 포함, 네트워크 일치). 깊이와 상관없이 그 키를 뿌리로 쓰는 슬롯(지문 = 그 키의 지문). 시드처럼 xpub·주소·서명·멀티시그 모두 가능, 니모닉 화면만 없음.
- **WIF:** 압축 키만, 네트워크 일치. 단일 키 슬롯: 그 키 하나로 P2WPKH·P2SH-P2WPKH·P2PKH·P2TR(키 경로) 주소 보기, PSBT 입력은 **스크립트가 그 키로 만들어졌는지**로 판정(경로 주장 불필요), 서명. xpub·멀티시그·BIP-85는 없음.
- 슬롯 표시: "시드 / XPRV / WIF"와 지문, 원래 원칙(새 시드는 주사위·동전으로만)은 그대로 — 가져오기는 이미 있는 키를 불러오는 것.
- 시험: rust-bitcoin으로 만든 PSBT에 서명하고 독립 검증, 다른 키·다른 네트워크·비압축 WIF 거부.

## 9. 시뮬레이터 가상 SD

- 화면 옆 "SD 카드" 패널: 넣기/빼기, 파일 끌어다 놓기(우리 FAT 코드가 가상 카드 이미지에 씀), 카드의 파일 목록과 내려받기(우리 FAT 코드가 읽음), 카드 비우기·포맷.
- 실제 FAT 코드가 그대로 돌아가므로 시뮬레이터에서도 파일시스템이 시험된다.

## 10. 보드 (H 트랙) — v3 (2026-11)

기준(사용자 지정): **최근 출시 · 여러 해 생산 약속 · 통신 모듈 없음(있으면 물리적으로 제거) · 물리 키보드(CardKB) 부착 · 화면·카메라·microSD**. 비교표·제거 정책·근거는 [M8_SURVEY.md §7](../M8_SURVEY.md).

- **1순위: STM32N6570-DK + 이더넷 제거** — 2024-12 출시, ST 10년 롤링 공급(2025년 기준 2035년까지). 5" **800×480** 터치 화면이라 지금 UI·시뮬레이터를 그대로 쓴다. 5 MP 카메라 모듈 포함, microSD, SRAM 4.2 MB + PSRAM 32 MB. 이더넷 PHY(RTL8211F)와 RJ45를 납땜으로 떼어 내고, 부팅 때마다 MDIO 비트뱅으로 PHY가 없는지 확인한다(응답하면 서명 거부). CardKB는 아두이노 D14/D15(I2C1)와 5 V 핀에 연결한다. Cortex-M55(`thumbv8m.main-none-eabihf`) — 지금 크레이트가 그대로 빌드된다.
- 대가: 납땜 제거(되돌릴 수 없음 → 보드 2대), embassy 지원이 확인되지 않아 화면·카메라·SD·I2C 드라이버를 직접 작성(H2).
- 2순위: **STM32H7S78-DK + Wi-Fi 도터보드 분리 + 이더넷 제거** — 800×480, Cortex-M7(지금 빌드 대상과 같음). 카메라 모듈은 별매, 떼어 낼 통신 모듈이 둘.
- 3순위: **Waveshare RP2350-Touch-LCD-3.5-C** — 통신 모듈이 아예 없어 제거 작업이 필요 없음. 대신 UI를 320×480으로 재배치, RAM 520 KB.
- 보류: ESP32-P4 보드들(Tab5·Function-EV-Board·DNESP32P4M — 칩 v1.3 → v3.2 비호환 전환, 러스트 지원 일부 불안정), NXP MIMXRT700-EVK. 탈락: STM32H747I-DISCO(2019년), STM32U5G9J-DK2(카메라·SD 없음), 무선이 주 칩에 든 키보드 일체형 기기(Cardputer·T-Deck), 카메라 없는 PicoCalc.
- 보안 칩(ATECC608 등) 필요 여부는 M10(보안 저장, 로드맵 v3 번호)에서 고른 칩의 OTP·서명 부팅 기준으로 판단.

## 12. 커밋 단위

1. **M8-1 FAT 읽기:** 블록 장치, MBR·BPB, FAT16/32, 디렉터리·긴 이름, 파일 읽기, 안전 검사 + rust-fatfs 비교 + 퍼징
2. **M8-2 FAT 쓰기:** 새 파일(긴 이름)·지우기·번호 붙이기·포맷, 쓰기 순서 + rust-fatfs 비교

4. **M8-4 파일 관리자:** 탐색·정보·텍스트 보기·종류별 열기·지우기·포맷
5. **M8-5 PSBT·메시지 파일:** 읽기(인코딩 판별·크기 상한), 검토·서명, 전체 PSBT 저장(이름 규칙), 원본 지우기 설정, 메시지 `.txt` → `.sig`

## 13. 시험

- **FAT:** rust-fatfs로 만든 이미지(FAT16·FAT32, 긴 이름, 하위 폴더, 조각난 파일) 읽기 일치, 우리가 쓴 이미지를 rust-fatfs로 읽어 일치, 포맷한 이미지를 rust-fatfs가 마운트.
- **악성 파일시스템:** 고리 체인, 교차 체인, 범위 밖 클러스터, 0 섹터 크기, 거짓 파일 크기, 끝없는 디렉터리, 깨진 긴 이름, FAT 두 벌 불일치 → 거부, 패닉 없음.
- **악성 파일:** 거대 PSBT, 잘못된 인코딩, 바꿔치기한 지갑 파일(태그 불일치), 약화 설정 파일, 비밀 단어가 든 텍스트(그냥 텍스트로 취급, 불러오지 않음).
- **BIP-85:** 본문 벡터 + embit 고정 벡터.
- **서명:** SD에서 읽은 PSBT의 서명을 rust-bitcoin으로 검증, 전체 PSBT 출력이 원본 + 우리 서명과 같음.
- **화면:** 배치 검사 영·한.

### 계획과 달라진 점

- FAT 두 벌 중 첫 벌만 쓰는 대신 **읽을 때마다 두 벌을 비교**한다(엄격). FAT 미러링을 끈 카드는 지원하지 않는다.
- 통신 칩 탐지는 "서명 거부"보다 강하게 **기기 잠금**: 시드·지갑·버퍼를 지우고 잠금 화면만 남는다.
- WIF 슬롯은 내부적으로 체인코드 0인 XPRV로 담고, 단일 키 표시로 xpub·멀티시그·BIP-85·경로 유도를 막는다.
- 원본 지우기 설정은 기기에서만 바꾼다(SettingsQR·설정 파일에 넣지 않음).
- QR 버퍼와 SD 버퍼를 나눴다: 스캔 수집 32 KB, SD PSBT 128 KB(작업 버퍼 144 KB). 실기기는 PSRAM에 둔다(H2).
- Sparrow 실제 왕복(아래 15장)은 사용자 확인 항목. 자동 시험은 rust-bitcoin 독립 검증으로 대신했다.

## 15. Sparrow SD 왕복 안내 (Signet)

메뉴 이름은 Sparrow 버전에 따라 조금 다를 수 있다. 시뮬레이터에서는 화면 옆 **microSD card** 패널이 컴퓨터 역할을 한다(파일 복사 = "Copy files to card…" 또는 끌어다 놓기, 꺼내기 = 목록의 내려받기).

**준비**
1. Sparrow: Settings > Network = Signet. Bitpunk: 설정 > 네트워크 = Signet, 시험용 시드를 주사위·동전으로 만들거나 불러온다.
2. SD 카드가 FAT32/FAT16이 아니면 Bitpunk에서 주 메뉴 > SD 카드 > 카드 포맷(확인 두 번).

**단일 서명 지갑 등록**
3. Bitpunk: 시드 > 시드 선택 > xpub 내보내기 → 형식을 고르고 QR 화면에서 <kbd>S</kbd> → 카드에 `bitpunk-<지문>.json`(네 가지 스크립트의 계정 xpub, Coldcard Generic JSON 모양) 저장.
4. Sparrow: File > New Wallet → Policy Single Signature, Script Native SegWit → Keystores: Airgapped Hardware Wallet > Coldcard > Import File… → `bitpunk-<지문>.json`.
5. Sparrow 받기 탭 #0과 Bitpunk 주소 화면(받기 #0)이 같은지 대조.

**지출**
6. Signet 수도꼭지에서 받기 #0으로 코인을 받는다.
7. Sparrow Send → Create Transaction → Finalize Transaction for Signing → **Save Transaction** → 카드에 `이름.psbt` 저장.
8. Bitpunk: 주 메뉴 > SD 카드 > PSBT 서명 → 파일 선택 → 검토(받는 사람·거스름·수수료) → 서명 → **SD 카드에 저장** → `이름-signed.psbt`. 화면 안내대로 카드를 뺀다.
9. Sparrow: File > Open Transaction > File… → `이름-signed.psbt` → 서명 완료 확인 → Broadcast Transaction.

**2-of-3 (M7 지갑)**
10. 멀티시그 키: Bitpunk 도구 > 멀티시그 지갑 > 내 멀티시그 키 내보내기 → QR 화면에서 <kbd>S</kbd> → `ccxp-<지문>.json` → Sparrow 멀티시그 지갑(Policy Multi Signature)의 Keystore에서 Airgapped Hardware Wallet > Coldcard > Import File…
11. 지갑 등록 후 Bitpunk 지갑 > 지갑 QR 내보내기 > "디스크립터 (QR 한 장)" QR 화면에서 <kbd>S</kbd>(디스크립터 `.txt`, Sparrow File > Import Wallet에서 읽음), 같은 목록의 "Bitpunk 지갑 파일"로 `.bpw`를 카드에 저장한다. `.bpw`는 다음 세션에 파일 관리자에서 열면 같은 시드가 불러와져 있을 때 **코드 입력 없이** 등록된다(태그를 시드로 확인하고 등록 규칙을 다시 검사).
12. 서명 순서는 7~9와 같다. 멀티시그 결과 이름은 `이름-signed-<지문>.psbt`라서 다른 서명자의 파일과 겹치지 않는다. 결과는 전체 PSBT이므로 다음 서명자가 그 파일로 바로 이어 서명할 수 있다.

**지키면 좋은 습관**
- 카드에는 PSBT·xpub·지갑 파일만. 시드 단어·개인키·BIP-85 결과는 Bitpunk가 카드에 쓰지 않으며, 텍스트 파일로 넣어도 불러오지 않는다.
- 서명이 끝난 PSBT 원본은 거래 기록이 남으므로 필요하면 설정 > "SD: 원본 PSBT 지우기"를 켠다(플래시 메모리는 지운 내용이 남을 수 있다).
- 카드를 오래 꽂아 두지 않는다: Bitpunk는 작업마다 카드 전원을 켜고 끈다.
