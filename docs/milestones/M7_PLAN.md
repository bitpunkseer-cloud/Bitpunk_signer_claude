# M7 구현 계획 (v1) — 멀티시그 · 디스크립터

상태: **구현 완료 (2026-11-22)** · 승인 2026-11-21 (결정 1~8 모두 권장안) · 근거: [M7_SURVEY.md](../M7_SURVEY.md) (9개 레퍼런스 + embit 내부·히스토리 + BIP-48/67/129/174/370/380~389/388 전수조사)

## 0. 원칙 — 보안 극대화

| 원칙 | 내용 | 가져온 곳 |
|---|---|---|
| **등록된 지갑만 서명** | 멀티시그 입력이 등록 지갑과 맞지 않으면 거부. "그래도 서명"·"PSBT 신뢰" 모드 없음 | CC 기본값, PP, SP (JD·SS·KX의 "등록 없이 서명"은 약점) |
| **PSBT 메타데이터는 힌트일 뿐** | 스크립트·주소는 등록 기록의 xpub에서 **다시 만든 것만** 믿는다. 경로는 (가지, 번호)를 찾는 데만 쓰고, 모순이면 공격으로 판정 | CC 재구성 + SS의 claimed/verified 구분 |
| **저장 공간이 없어도 등록 강제** | M9 보안 저장 전까지는 **시드로 만든 HMAC 지갑 코드**로 세션 사이 변조를 막는다 | BIP-388 / Ledger의 등록 증명 HMAC |
| **에어갭 생성** | 컴퓨터를 거치지 않고 공동서명자 기기 화면의 xpub QR을 Bitpunk가 **직접** 스캔해 지갑을 만든다 (생성 단계의 xpub 바꿔치기 차단) | CC의 SD 에어갭 생성을 QR로 |
| **독립 구현** | 디스크립터·PSBT 파서, BIP-32, 서명 해시, secp256k1 모두 자체 코드. embit은 **시험의 바깥 오라클**로만 (코드 참고 금지) | 사용자 구성(embit 3대)의 공통 모드 장애 대응 |
| **거부는 경고로 낮추지 않음** | 이유와 함께 거부. 경고는 사용자가 판단할 수 있는 것(비표준 경로, 큰 거스름 번호)만 | M5 원칙 유지 |

## 1. 목표

**완료 기준**
- Signet 2-of-3 {Bitpunk, SeedSigner, Krux 또는 Specter DIY}: Bitpunk에서 **에어갭 생성** → 디스크립터 QR을 Sparrow(감시 전용)와 embit 기기에 등록 → 받기 주소 #0이 Bitpunk와 embit 기기에서 **같은 주소**로 나옴 → Sparrow의 지출 PSBT를 Bitpunk + embit 기기 하나가 서명 → Sparrow가 브로드캐스트
- Sparrow에서 만든 지갑(디스크립터·Coldcard 텍스트)을 가져와도 **같은 지갑 코드**가 나옴
- 공격 시험(CC·PP·SS·SP 시나리오 + 자체) 전부 거부, 패닉 없음
- 주소·스크립트가 BIP·Bitcoin Core 벡터, rust-miniscript, embit 고정 벡터와 **모두** 일치

## 2. 범위

**포함:** `wsh(sortedmulti)`, `sh(wsh(sortedmulti))`, 1 ≤ M ≤ N ≤ 15, 메인넷·테스트넷·시그넷, 가져오기·생성·내보내기, 멀티시그 PSBT 서명, 멀티시그 주소 표시·검증, 지갑 코드, 세션 등록부(세션당 최대 4개, RAM 예산에 따라 조정).

**제외:**

| 항목 | 이유 | 시기 |
|---|---|---|
| 비정렬 `multi` | 순서 실수·혼동 여지, 사용자 기기·Sparrow 모두 `sortedmulti` 기본 (결정 4) | 필요 시 |
| 레거시 P2SH (BIP-45) | 가변성, 수수료, 사용자 기기 대부분 비권장 | 안 함 |
| Taproot 멀티시그 · miniscript | 정책 엔진 필요 | M10 |
| BSMS (BIP-129) | Sparrow 미지원, AES 추가 구현 필요 (결정 7) | M10 검토 |
| PSBT v2 (BIP-370) | 사용자 흐름(Sparrow)은 v0, 파서 표면 최소화 — embit의 최근 수정도 이 영역 (결정 6) | 필요 시 |
| 영구 저장 | SD는 M8(전체 HMAC 태그로 자동 검증), 내부 저장은 M9 | M8·M9 |

## 3. 지갑 모델

```
MultisigWallet { network, script: Wsh | ShWsh, m, keys: [Cosigner; N], name }
Cosigner      { fingerprint[4], origin path (≤ 8단계), xpub(깊이, 부모 지문, 자식 번호, 체인코드, 공개키) }
뒤 경로        모든 키 공통 <0;1>/* (받기 0, 거스름 1). "/0/*"만 있으면 거스름 /1/*로 간주
```

- 키 순서는 `sortedmulti`라 의미가 없으므로 **공개키 기준으로 정렬해 보관** (같은 지갑이면 어디서 가져와도 같은 기록).
- **정규 바이트열** (지갑 코드·중복 판정용): `"BPMS1" ‖ 네트워크 ‖ 스크립트 종류 ‖ M ‖ N ‖ 키마다(지문 ‖ 경로 길이 ‖ 경로 ‖ 체인코드 ‖ 공개키)`. 이름은 넣지 않음.

## 4. 등록 규칙 (어기면 거부, 이유 표시)

| # | 규칙 | 근거 |
|---|---|---|
| R1 | 문법을 엄격히: 체크섬이 있으면 일치해야 함, 알 수 없는 함수·공백·중첩 거부, M/N 범위 1..15, 키 수 = N | BIP-380, CC |
| R2 | **이 시드의 키가 정확히 한 번**: 지문이 같은 키의 xpub이 이 시드에서 그 경로로 유도한 것과 체인코드·공개키까지 같아야 함 (다르면 "패스프레이즈가 다르거나 바꿔치기") | CC, JD |
| R3 | 우리 지문이 두 번 / **다른 지문 아래 우리 키** / 다른 키끼리 같은 공개키·xpub → 거부 (N을 몰래 줄이는 공격) | CC, BIP-388 |
| R4 | 모든 키에 origin(`[지문/경로]`) 필수, **xpub 깊이 = 경로 길이**, 깊이 1이면 부모 지문 = 그 키의 지문 | CC |
| R5 | xpub 뒤 경로에 하드닝 금지, `<0;1>/*` 또는 `/0/*`만, 모든 키 같은 뒤 경로 | CC, JD, OK, BIP-388 |
| R6 | 네트워크: xpub 버전(xpub/tpub)과 경로의 코인 번호가 지금 네트워크와 일치, 섞이면 거부 | 전부 |
| R7 | SLIP-132(`Zpub`/`Ypub`…)로 온 키는 버전이 스크립트 종류와 맞아야 함 (Zpub로 P2SH-P2WSH 등록 거부) | 혼동 공격 차단 (T6) |
| R8 | 우리 키 경로가 BIP-48(`48'/코인'/계정'/2'` 또는 `1'`, 스크립트 종류와 일치)이 아니면 **경고 화면**(이유 표시 후 계속 가능). 다른 키도 비표준이면 표시 | CC |
| R9 | `multi`(비정렬) 거부 | CC 기본값 |
| R10 | 같은 세션에 같은 지갑 → "이미 등록됨". **같은 키인데 M·스크립트 종류만 다른 지갑** → 강한 경고 (M 낮추기 혼동) | CC 비슷한 지갑 판정 |
| R11 | 이름: 인쇄 가능한 ASCII 1~20자, 없으면 "MS-{코드 앞 4자}" | — |

## 5. 지갑 코드 — 저장 공간 없이 등록 유지

- **키:** `K = HMAC-SHA512(키 = "Bitpunk wallet code v1", 메시지 = 마스터 체인코드 ‖ 마스터 개인키)`의 앞 32바이트. 시드·패스프레이즈가 같으면 어느 Bitpunk에서든 같은 키.
- **코드:** `HMAC-SHA256(K, 정규 바이트열)`의 앞 40비트를 Crockford base32 8자로 → 예 `7KQ2-M9XD`.
- **왜 키가 필요한가:** 키 없는 해시를 8자로 줄이면, 공격자가 자기 xpub을 바꿔 가며 **같은 8자가 나오는 가짜 지갑을 오프라인으로** 찾을 수 있다(약 2^40회, 현실적). HMAC은 시드 없이는 계산할 수 없어 공격자는 기기에 한 번씩 넣어 보는 수밖에 없고, 한 번에 맞을 확률은 2^-40.
- **코드는 비밀이 아니다** (알아도 다른 지갑의 코드를 만들 수 없음) → 지갑 카드에 적어 둔다.
- **처음 등록:** 전체 확인(4장·7장) 후 코드 표시 → "적었습니다" → **코드를 다시 입력**해 받아 적기 실수를 잡는다.
- **다음 세션:** 디스크립터를 다시 스캔하거나, PSBT의 전역 xpub·스크립트로 지갑을 재구성 → **코드를 키보드로 입력**해야 등록 (눈 비교 아님, 결정 1). 맞으면 서명자별 확인을 생략, 틀리면 "처음 등록한 지갑과 구성이 다릅니다"로 거부.
- **코드를 잃어버리면:** 처음처럼 전체 확인으로 다시 등록 → 같은 코드가 나온다 (결정적).
- **M8:** SD에 디스크립터 + 256비트 전체 태그 → 불러올 때 자동 검증(입력 불필요). **M9:** 내부 보안 저장.

## 6. 등록 경로

### 6.1 에어갭 생성 (권장)
도구 > 멀티시그 > 새로 만들기: 스크립트 종류(P2WSH 기본) → M, N → **이 기기 키**(BIP-48, 계정 0, 바꿀 수 있음) 자동 → 공동서명자 xpub N−1개를 차례로 스캔.
- 읽는 형식: 키 표현식 텍스트(`[fp/48h/0h/0h/2h]xpub…`, SLIP-132 포함), UR `crypto-account`·`crypto-hdkey`, Coldcard xpub JSON. SeedSigner·Krux·Specter DIY의 xpub 내보내기를 모두 포함.
- 스캔할 때마다 지문·경로·xpub을 보여 주고 **그 기기 화면과 대조**하도록 안내, R3~R7은 그 자리에서 검사.
- 끝나면 요약 → 첫 주소 → 지갑 코드 → **디스크립터 QR**(Sparrow·SS·KX·SP에 등록).

### 6.2 가져오기
디스크립터 텍스트, JSON, Coldcard 텍스트, UR `crypto-output`(멀티시그 태그)·`bytes`, BBQr. 같은 규칙, 같은 화면 (서명자 페이지를 **모두 넘겨야** 다음).

### 6.3 서명 중 재등록
PSBT가 등록되지 않은 멀티시그를 쓰면: 전역 xpub으로 재구성이 되면 "이 지갑의 코드를 입력하세요", 안 되면 "먼저 멀티시그 메뉴에서 지갑을 불러오세요". **처음 등록은 서명 흐름에서 받지 않는다** (서두르는 상황에서 확인 생략 방지, CC의 "Verify Only").

## 7. 화면

- **등록 요약:** 이름, `2-of-3 · P2WSH`, 네트워크, 이 기기 키 위치, 경고(비표준 경로 등)
- **서명자 i/N:** 지문(크게), 경로, xpub 전체를 4자씩 끊어 여러 줄, "이 기기" 표시
- **첫 주소:** 받기 #0, 거스름 #0 (+QR) — "embit 기기에서도 같은 주소인지 확인하세요" (서로 다른 코드베이스가 같은 결과를 내는지 대조)
- **지갑 코드:** 표시 → 재입력
- **지갑 목록** (도구 > 멀티시그): 이름·정책·코드 / 항목: 주소 보기(받기·거스름 i, QR), 서명자 보기, 내보내기, 세션에서 지우기
- **서명 검토:** 머리말에 지갑 이름·정책·코드, 서명 현황 `1/2 → 서명 후 2/2 (완료)`, 거스름에 "등록 지갑 #i로 검증", 다른 등록 지갑으로 가는 출력은 "지갑 Y 받기 #i"로 표시하되 **보내는 금액으로 계산**

## 8. 서명 규칙

| # | 규칙 | 판정 |
|---|---|---|
| S1 | 입력 스크립트: P2WSH는 `witness_script`, P2SH-P2WSH는 `redeem_script`(=`0020‖sha256(ws)`) + `witness_script` 필수. `ws`는 **정확히** `OP_m <33바이트 압축 키>×n OP_n OP_CHECKMULTISIG` (최소 푸시), 키는 BIP-67 순서 | 없거나 다르면 오류 |
| S2 | 입력의 (가지, 번호): 등록 키 중 하나 이상의 `bip32_derivation`에서 얻음. 다른 키 항목이 있으면 **모두 같은 (가지, 번호)**이고 공개키가 등록 xpub 유도값과 같아야 함 | 모순이면 공격 |
| S3 | **재구성:** 등록 xpub N개를 (가지, 번호)로 유도 → 정렬 → 스크립트 → `ws`와 바이트 일치 → scriptPubKey가 UTXO와 일치 | 다르면 공격 |
| S4 | 이 시드 지문을 주장하는데 어느 등록 지갑으로도 재구성되지 않는 입력 → **거부** (poisoned input) | 공격 |
| S5 | 멀티시그 입력은 **모두 같은 지갑**, 단일 서명 입력과 섞이면 거부. 우리 키가 없는 외부 입력은 M5 규칙 그대로 | 오류 |
| S6 | **거스름:** 출력에 등록 키의 경로가 있으면 같은 방식으로 재구성해 scriptPubKey(·`ws`)가 일치할 때만 거스름(가지 1) / 자기 전송(가지 0). 이 시드를 주장하는데 재구성이 안 되면 **공격**(M5의 `ChangeContradiction`과 같은 등급). 경로가 없거나 다른 지갑 모양이면 그냥 받는 사람 | CC, PP |
| S7 | 거스름 번호가 입력 번호보다 훨씬 크면 경고 (M5 `ChangeIndexFar`, 간격 10,000) | 경고 |
| S8 | 전역 xpub: 등록 키의 origin과 같은 경로를 주장하면서 xpub이 다르면 거부, 관계없는 전역 xpub은 무시 | 공격 |
| S9 | **다른 서명자의 부분 서명 검증:** 공개키가 그 입력 스크립트에 있고 서명이 이 거래의 서명 해시로 유효해야 서명 현황에 셈. 아니면 경고 + 제외 (결정 8) — embit 기기의 서명을 독립 코드로 한 번 더 확인 | 경고 |
| S10 | 서명: 이 시드에서 (가지, 번호)로 키를 유도해 스크립트 안의 우리 자리와 같은지 확인 → BIP-143(스크립트 코드 = `ws`) → RFC 6979 + low-R → 자체 검증 → `partial_sig` 추가. 최종화는 하지 않음 (코디네이터 몫) | M5 절차 |
| S11 | 수수료·SIGHASH·UTXO 기억·금액 범위 등 M5 검사는 그대로 | M5 |

## 9. 내보내기

- **이 기기 BIP-48 xpub** (코디네이터용): 키 표현식 텍스트, UR `crypto-account`(멀티시그 항목, 태그 조합은 Sparrow·Keystone 출력과 대조해 확정), Coldcard xpub JSON(`p2wsh`, `p2sh_p2wsh`) — Sparrow·Nunchuk·Specter Desktop·Keeper가 읽음. 계정 번호 선택.
- **등록 지갑:** 디스크립터(체크섬 포함, `<0;1>` 한 줄 또는 `/0/*`·`/1/*` 두 줄 — 옛 펌웨어 호환), Coldcard 텍스트. 큰 QR은 UR `bytes` / BBQr 애니메이션.

## 10. 주소 검증 확장 (M6 이어서)

- 멀티시그 주소 스캔 → 이번 세션의 등록 지갑에서 받기·거스름 각 0번부터 1,000개씩 탐색(이어서 가능) → "지갑 X · 받기 #i". 지금의 `TargetError::Multisig` 거부를 이 경로로 바꿈.
- 주소 보기 i (QR): Sparrow가 보여 준 받기 주소를 **Bitpunk에서 확인한 뒤에만** 쓰도록 안내 (받기 주소 바꿔치기 T2).

## 11. 감시 전용 검증 (결정 5)

우리 키가 없는 지갑도 경고 후 등록(SP 방식)해 PSBT를 **서명 없이 검증**만 한다: 입력 재구성, 거스름, 수수료, 부분 서명 검증, 요약. SeedSigner·Krux·Specter DIY 둘이 서명하는 경우에도 독립 코드의 판정을 한 번 거칠 수 있다. 이때 지갑 코드 키는 등록 때 고른 시드에서 만든다.

## 12. 권장 사용 절차 (사용자 문서에 넣음)

1. 구성: **{Bitpunk, embit 기기 2대} 2-of-3** — 남는 embit 기기는 예비.
2. 매 지출: **Bitpunk가 먼저 검토·서명**, 두 번째 서명은 embit 기기. 그러면 서명 두 개 중 하나는 늘 독립 코드에서 나온다. (2-of-3 정책 자체로는 강제되지 않음 — 강제가 필요하면 M10 miniscript: `Bitpunk 필수 + 나머지 1-of-2` + 시간잠금 복구)
3. 생성: Bitpunk 에어갭 생성, 각 xpub은 그 기기 화면과 대조, 받기 #0을 Bitpunk와 embit 기기 양쪽에서 확인.
4. embit 기기에도 디스크립터를 등록/불러와 거스름 검증을 켠다 (SeedSigner는 세션마다).
5. 백업: 시드 3개 + **지갑 카드**(디스크립터 QR 인쇄 + 지갑 코드). 멀티시그는 디스크립터가 없으면 복구가 매우 어렵다.

## 17. 2-of-3 구성 안내 (Signet, Sparrow + SeedSigner + Krux 또는 Specter DIY + Bitpunk)

기기 메뉴 이름은 펌웨어 버전에 따라 조금 다를 수 있다.

**준비**
1. Sparrow: Settings > Network = Signet. Bitpunk(시뮬레이터): 설정 > 네트워크 = Signet, 시험용 시드를 주사위·동전으로 만들거나 불러온다. SeedSigner·Krux·Specter DIY도 테스트넷/Signet으로 설정한다.

**지갑 만들기 — 컴퓨터를 거치지 않고**
2. 각 공동서명자에서 멀티시그(BIP-48, Native SegWit) xpub QR을 띄운다: SeedSigner는 Export Xpub > Multisig > Native SegWit, Krux는 Extended Public Key > Multisig, Specter DIY는 멀티시그 xpub 화면.
3. Bitpunk: 도구 > 멀티시그 지갑 > 지갑 만들기 (에어갭) → P2WSH, 2, 3 → Enter. 이 기기 키가 1번으로 들어간다.
4. "공동서명자 2 스캔" → SeedSigner 화면의 QR → Bitpunk가 보여 주는 **지문·경로·xpub을 SeedSigner 화면과 하나하나 대조** → "이 공동서명자 추가". Krux(또는 Specter DIY)로 3번도 같은 방법.
5. 첫 주소 화면의 **받기 #0**을 적어 둔다 → 지갑 코드를 **지갑 백업 카드에 적고** 다시 입력 → 등록됨.
6. 지갑 QR 내보내기 → "디스크립터 (QR 한 장)"를 Sparrow(새 지갑 > Settings에서 디스크립터 스캔)와 Krux·Specter DIY에 등록, SeedSigner에는 "Coldcard 파일 (UR)" 또는 "디스크립터 (애니메이션)".
7. **받기 #0 대조:** Sparrow 받기 탭 #0, Bitpunk(지갑 > 주소 > 받기 #0), Krux/Specter DIY의 주소 #0이 모두 같아야 한다. 서로 다른 코드베이스(Bitpunk ↔ embit ↔ Sparrow)가 같은 지갑을 읽었다는 확인이다.

**지출**
8. Signet 수도꼭지에서 받기 #0으로 코인을 받는다.
9. Sparrow에서 송금 PSBT를 만들고 QR(UR)로 띄운다 → **Bitpunk가 먼저** 스캔: 머리말에 지갑 이름·2-of-3·코드, "서명: 지금 0 / 2, 서명하면 1" → 출력(받는 사람, 거스름은 "지갑 … 거스름 #i") → 수수료 → 서명 → 서명 QR(UR)을 Sparrow로.
10. Sparrow가 합친 PSBT를 SeedSigner(또는 Krux)에 서명받아 2/2가 되면 방송한다.

**다음 세션(전원을 껐다 켠 뒤)**
11. 지갑은 세션 동안만 기억된다(M8 SD·M9 보안 저장 전). 디스크립터를 다시 스캔하고 "지갑 코드가 있습니다"를 골라 적어 둔 코드를 입력하거나, 그냥 PSBT를 스캔하면 Bitpunk가 PSBT의 전역 xpub으로 지갑을 재구성해 코드를 묻는다(Sparrow는 멀티시그 PSBT에 전역 xpub을 넣는다; 없으면 디스크립터를 먼저 스캔). 코드가 맞아야만 등록된다 — 지갑이 조금이라도 바뀌었으면 코드가 맞지 않는다.

**지키면 좋은 습관**
- 매 지출에서 Bitpunk를 두 서명자 중 하나로: embit 공통 버그 하나로 두 서명이 함께 뚫리는 일을 막는다.
- 지갑 백업 카드에 디스크립터 QR과 지갑 코드를 함께 보관한다(시드 3개와 따로).
- Bitpunk 키가 없는 기존 3대 embit 지갑도 Bitpunk에 등록하면(감시 전용) 서명 전에 독립 코드로 검증할 수 있다.
