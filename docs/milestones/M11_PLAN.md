# M11 구현 계획 (v1) — 고급 백업 · 도구

상태: **제안 (2026-11-25)** — 승인 전 · 근거: [M11_SURVEY.md](../M11_SURVEY.md) · 화면은 [UX 언어 v1.0](../UX_LANGUAGE.md)을 따른다.

## 1. 목표

- 시드를 **잃지 않게**(분할 백업: Seed XOR·SLIP-39, 금속판 형식) 하고, 기기에 쌓인 것(보관함·지갑·설정·노트)을 **SD에 암호화 백업**해 새 기기로 옮길 수 있게 한다.
- QWERTY를 살린 **오프라인 도구**: 보안 노트·비밀번호, OTP(TOTP/HOTP), 받은 데이터 보기.
- 기존 기능은 그대로(기능 대장·M8 골든 출력·과제 키 수). 동결은 계속 파일 단위(새 파일만).

## 2. 범위 제안

| 넣음 | 빼거나 미룸 |
|---|---|
| 암호화 전체 백업 + 검증 + 복원 | Coldcard 7z 호환(PC에서 열기) |
| SLIP-39 불러오기 + 주사위로 새 SLIP-39 지갑과 조각 | BIP-39 지갑을 SLIP-39로 바꾸기(표준 없음 → Seed XOR로) |
| Seed XOR 분할·복원 | — |
| Tinyseed / Stackbit 1248 보기·격자 입력 | 카메라로 금속판 판독 |
| 입력을 마치기 전 전체 단어 검토·수정(기존 고치기 화면 확장) | 불러온 시드 단어 바꾸기 |
| 보안 노트·비밀번호 (보관함 저장) | — |
| HOTP + TOTP (켤 때 시각 입력) | — |
| 데이터 보기(QR·파일의 텍스트/hex) | 변환·KEF 암호화 |
| — | **Miniscript → 별도 마일스톤**(결정 1) |

## 3. 설계 요점

### 3-1. 암호화 백업 (`.bpb`)
- 내용: 보관함 레코드(시드·지갑·설정) + 노트·OTP. 패스프레이즈·서명 기록·세션 로그는 넣지 않는다(보관함과 같음).
- 암호: **BIP-39 단어 12개**(체크섬 없음, 132비트)를 보이고 퀴즈로 확인 → Argon2id(보관함과 같은 비용) → ChaCha20-Poly1305. 머리말에 형식 버전·KDF 값·만든 기기 지문(평문, 인증됨).
- 단어의 출처(결정 3): 주사위·동전(권장, 우리 원칙과 같음) / 보안 칩 난수 / BIP-85.
- 같은 암호를 다음 백업에 다시 쓸지 묻고, 쓰면 보관함에 둔다(Coldcard 방식).
- **검증**: 암호를 넣으면 풀어서 요약(시드 지문들·지갑 수·노트 수)만 보이고 아무것도 불러오지 않는다. **복원**: 보관함이 열려 있으면 그 안으로(겹치는 것 건너뜀), 없으면 이번 세션 RAM으로.

### 3-2. SLIP-39
- 새 슬롯 종류 "SLIP-39"(마스터 비밀 16/32바이트 → BIP-32 시드). 보관함에도 저장(새 레코드 형식).
- 불러오기: 조각을 단어로 하나씩 입력(첫 두 단어로 묶음 확인, RS1024 즉시 검사, 그룹·임계값 진행 표시) → 패스프레이즈(있으면) → 슬롯.
- 만들기: 주사위·동전으로 마스터 비밀 → 그룹 구성(예: 1단계 3중 2, 또는 2단계) → 조각마다 단어 표시 + 퀴즈.
- 조각 다항식 계수·식별자(결정 5): 마스터 비밀과 구성(그룹·임계값)에서 HMAC으로 결정적 유도(권장: 같은 구성이면 같은 조각이 다시 나와 기록을 확인할 수 있고, 구성이 다르면 다른 다항식이라 섞어도 새 정보가 없다). 선택으로 주사위를 섞을 수 있다(같은 주사위면 다시 같은 조각).
- SLIP-39 단어 목록 1024개(명세, MIT) 새 파일.

### 3-3. Seed XOR
- 분할: 불러온 BIP-39 시드 → 2~4조각. 조각마다 단어 표시 + 퀴즈. 원래 체크섬 단어를 함께 적도록 권함.
- 조각 생성(결정 5): **Coldcard 결정적 공식 그대로**(권장: Coldcard와 같은 조각, 다시 만들어 확인 가능). 로드맵의 "분할 무작위값도 주사위로" 검토 항목은 선택 기능 "주사위 섞기"로 넣는다 — 주사위 값을 공식 입력에 더해, 조각을 모두 모은 공격자도 Coldcard 공식으로 쪼갠 시드임을 확인할 수 없게 한다(Coldcard 문서가 든 결정적 방식의 단점). 같은 주사위 기록이면 같은 조각이 다시 나온다.
- 복원: 조각을 차례로 입력(순서 무관) → 결과 지문과 체크섬 단어 표시 → 슬롯.

### 3-4. Tinyseed / Stackbit 1248
- 시드 옵션에 "금속판 형식": 단어 번호를 Tinyseed 격자(12비트)·Stackbit(4자리×1248) 그림으로, 12단어씩 넘김.
- 불러오기에 "격자로 입력": 칸을 켜고 끄며 단어 번호를 만들고, 마지막 단어 체크섬 비트는 자동.

### 3-5. 단어 검토
- 단어 입력을 마치면(체크섬이 맞아도) 전체 단어 격자를 한 번 보이고, 아무 단어나 골라 고칠 수 있게 한다(기존 체크섬 오류 화면을 넓힘). 과제 효율 시험에 키 하나(Enter)가 늘어나는 의도한 변경으로 기록.

### 3-6. 보안 노트 · 비밀번호
- 도구 > 노트: 노트(제목·본문), 비밀번호(제목·사용자·비밀번호·사이트·메모). 보기, QR, 지우기(WIPE). 보관함이 있어야 저장(없으면 이번 세션만).
- 비밀번호 생성: 주사위로 만든 단어·문자, 또는 BIP-85 비밀번호(이미 있음).
- 크기 한도: 노트 32개 · 노트당 1 KB 안팎(보관함 슬롯 크기 안).

### 3-7. HOTP / TOTP
- 등록: `otpauth://` QR 스캔 또는 base32 직접 입력. HMAC-SHA1(새 파일)·SHA-256·SHA-512, 6/8자리, 주기 30초.
- TOTP 시각: 켤 때마다 날짜·시각(UTC) 입력(결정 8). 보관함에 저장.

### 3-8. 데이터 보기
- 도구 > 데이터 보기: QR·SD 파일의 내용을 텍스트(인쇄 가능할 때)와 hex로, 길이·형식 추정(PSBT·디스크립터·xpub·주소 등은 해당 화면으로 안내).

## 6. 커밋 단위 (결정 1 권장안 기준)

1. **M11-0 기반:** 기능 대장 M11 절(의도한 변경 E1~), 시험 틀
2. **M11-1 SLIP-39 핵심:** GF(256) Shamir, RS1024, Feistel, 단어 목록 — 공식 `vectors.json` 전부 + Trezor 참조 구현 교차
3. **M11-2 SLIP-39 화면:** 조각 불러오기, 주사위로 만들기와 조각 표시·퀴즈, SLIP-39 슬롯·보관함 저장
4. **M11-3 Seed XOR:** 분할(Coldcard 공식)·복원, 문서 예제 벡터
5. **M11-4 금속판 형식:** Tinyseed·Stackbit 보기와 격자 입력
6. **M11-5 단어 검토:** 입력 끝 전체 격자 검토·수정
7. **M11-6 보안 노트·비밀번호:** 보관함 저장, 생성기, QR
8. **M11-7 OTP:** SHA-1(RFC 3174 벡터), HOTP/TOTP(RFC 4226/6238 벡터), otpauth 스캔, 시각 입력
9. **M11-8 암호화 백업:** `.bpb` 만들기·검증·복원, 전원 끊김·변조 시험
10. **M11-9 데이터 보기**
11. **M11-10 공격 시험·퍼징·시뮬레이터·문서·배포**
